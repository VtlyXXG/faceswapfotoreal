# Этап 1: перенос причёски тем же FLUX.2, без слов и без fal

Проверяется одна гипотеза: **причёска ребёнка переносится тем же вызовом, что и
лицо, если перестать её запрещать промптом.** Механика вокруг для этого уже
готова — маска вклейки есть объединение старой и новой головы, волосы в неё
входят, а освободившаяся зона накрывается плитой LaMa (`orphan_px` в мете).

Ручного описания причёски здесь нет вовсе: она берётся с фотографии, которая и
так уезжает в генерацию вторым референсом.

## Перед первым прогоном

Правки, без которых прогон невозможен, лежат в этом же коммите и должны доехать
до бокса:

```
ssh deploy@<хост> 'cd <репозиторий> && git pull && sudo systemctl restart gpu-inference'
ssh -f -N -L 8300:127.0.0.1:8300 deploy@<хост>
curl -s http://127.0.0.1:8300/health/ready
```

Что они добавляют: поля `prompt` и `scale_mode` в запрос `/v1/demo-render`. До
них каждый вариант формулировки стоил бы правки `.env` и перезапуска сервиса на
боксе; после — одной строки в команде. Умолчания не изменились: без этих полей
сервер ведёт себя ровно как раньше.

## Прогон

Набор берётся пробный (`tools/_probe.py`): три шаблона на три личности, среди
них `donor67` с афро-хвостиками — единственный кадр, на котором видно, переносится
ли ФОРМА причёски, а не только её цвет.

```
# 0. Опора: тот же seed, прежний промпт-запрет. Без неё сравнивать не с чем
python tools/probe_batch.py render --seed 1234 --prefix H0_ \
    --only dino1_id67 dino1_id68 dino2_id67 dino2_id68

# 1. Минимальная правка: из запрета убрана только причёска
python tools/probe_batch.py render --seed 1234 --prefix H1_ \
    --prompt-file tools/prompts/hair_v1.txt \
    --only dino1_id67 dino1_id68 dino2_id67 dino2_id68

python tools/probe_batch.py measure H0_ H1_
python tools/probe_batch.py sheets --out sheets_hair H0_ H1_
```

Четыре кадра на комплект — это примерно три минуты GPU. Смотреть листы глазами
обязательно: числа здесь вторичны, они сторожат регресс, а не решают.

## Что читать в результатах

| Колонка | Чего ждём | Тревога |
|---|---|---|
| **РАКУРС** (`pose_shift`) | на `dino2` держится около 0.01–0.05, как в `H0_` | скачок к 0.5 и выше — генератор перестал слушать запрет и распрямил опущенную голову. Это главный риск правки |
| **СХОДСТВО** | не ниже `H0_` в пределах разброса зерна | падение на всех кадрах сразу — причёска отъедает внимание модели от лица |
| **ПРЯДИ, СТРОГО** | около нуля | рост означает, что от прежней причёски остались куски: маска вклейки не накрыла новую форму |
| `orphan_px` в мете | вырастет, и это нормально | силуэты разошлись сильнее — ровно то, ради чего в пути стоит LaMa |
| `scale` в мете | близко к `H0_` | заметный уход — включился эффект `SCALE_MODE`, см. ниже |

## Если что-то пошло не так

**Голова села не того размера.** `SCALE_MODE="head"` меряет силуэт «волосы плюс
лицо». Пока причёска доставалась от шаблона, это было безопасно; с переносом
чужой причёски мерка неверна по построению — пышные волосы ужмут лицо, гладкие
раздуют. Лечится без деплоя:

```
python tools/probe_batch.py render --seed 1234 --prefix H1F_ \
    --prompt-file tools/prompts/hair_v1.txt --scale-mode face --only ...
```

**Поза поехала.** Пробовать `hair_v4.txt` — та же просьба, но запрет на ракурс
переформулирован жёстче и стоит после неё. Если и там ракурс уезжает, гипотеза
не подтвердилась: удержание позы и перенос причёски на этой модели конфликтуют.

**Причёска не переносится вовсе.** По очереди `hair_v2.txt` (перечисляет, что
именно брать: длину, форму, объём, фактуру, цвет) и `hair_v3.txt` (разводит
картинки по ролям: «первая — сцена, вторая — фотография ребёнка»).

Порядок вариантов не случаен: `v1` — наименьшее отличие от формулировки, которая
уже работает, и начинать надо с неё. Каждый следующий добавляет модели свободы, а
вместе с ней и риск потерять позу.

## Чего этот этап НЕ проверяет

Длинные волосы на шаблоне с коротко стриженным персонажем — самый тяжёлый случай:
модель обязана дорисовать то, что пряди закрывали. На пробном наборе такой пары
нет. Если этап пройден, брать её отдельно.
