# Фриланс-контур

Рабочие материалы для поиска и ведения заказов на замену лица на фото/обложке
(пайплайн — этот репозиторий: `ml-service` + `gpu-inference-server`, FLUX.2 +
LaMa). Не часть продукта, в прод не деплоится — это инструменты для реального
человека, который ведёт биржи руками.

## Почему это не полностью автономно

У сессии, которая это готовит, нет браузера с логином и нет доступа к
аккаунтам бирж (Kwork, FL.ru, Habr Freelance, Upwork, Fiverr, Telegram-чаты).
Пароли в чат передавать не нужно и не будет принято — это не защищённый канал
для credentials, а держать сессию залогиненной без контроля человека — риск,
которого стоит избегать. Рабочая схема поэтому такая:

1. Человек ищёт заказ на бирже и присылает текст задания (или ссылку — но
   ссылку прочитать не всегда получится, поэтому надёжнее текстом).
2. По тексту готовится: оценка заказа (1–10 по вероятности получить, риску,
   марже, срокам), персональный отклик под конкретное задание, 1–3 вопроса
   клиенту при необходимости.
3. Человек копирует отклик и отправляет сам.
4. Ответ клиента — снова текстом сюда; из него готовятся: уточняющие
   вопросы, аргументация цены, финальные условия.
5. Когда заказ подтверждён — уже здесь, в коде: сборка результата через
   пайплайн, проверка, подготовка сообщения о сдаче.

## Что нужно от человека на старте

- Текст конкретного задания с биржи (не пересказ — оригинал, там есть детали,
  которые меняют оценку и отклик).
- Фото/материалы клиента, когда они появятся (source + target для
  `/api/v1/personalize` или `/api/v1/covers`).
- Подтверждение цены и сроков перед тем, как их назвать клиенту — черновик
  готовится, финальное «да» на цифру — за человеком, если сумма выходит за
  диапазон в `pricing.md`.

## Файлы

- `pricing.md` — диапазоны цен, скорректировать после первых 5–10 реальных
  откликов и по факту конкурентов на конкретной бирже.
- `templates/` — не готовые тексты, а каркасы под платформу. Каждый отклик
  всё равно пишется под конкретное задание — шаблон только держит структуру
  и тон, характерный для площадки.
- `orders.md` — учёт заказов и отчётность (раздел 15 исходного ТЗ). Обновлять
  по каждому событию (отклик отправлен / ответ получен / заказ получен /
  сдан / оплачен), не пачками в конце.

## Что не делается никогда

- Не пишется, что это ИИ, если площадка/клиент не требует прямо это указать.
- Не придумываются отзывы, портфолио, кейсы, которых нет. Отклики опираются
  только на факт: пайплайн реально работает (можно показать пример прогона),
  без утверждений про стаж, число клиентов или сертификаты.
- Не подтверждается цена/сроки клиенту, если это выходит за диапазон в
  `pricing.md`, без подтверждения человека.
- Не выполняется работа с чужими персональными данными без явного согласия
  того, чьё фото используется.
