# Цены (черновой диапазон — уточнить по первым откликам)

Ориентир, не прайс-лист для клиента. Реальная цена в отклике — из этого
диапазона, скорректированная под объём, срок и то, что уже просит клиент.
После первых 5–10 откликов на конкретной бирже — пересмотреть вместе с
человеком: если конкуренты сильно ниже, обсудить, снижать диапазон или менять
позиционирование (не демпинговать автоматически, см. п.6 ТЗ).

## B2C — одно фото/обложка с лицом клиента (RU-биржи: Kwork, FL.ru, Habr)

| Услуга | Цена | Срок |
| --- | --- | --- |
| Замена лица на одном фото | 1500–2500 ₽ | 1–2 дня |
| Персонализация обложки (книга/постер, под печать) | 2500–4000 ₽ | 2–3 дня |
| Пакет 5 фото одного клиента | −15% к сумме за штуку | +1 день |
| Пакет 10+ фото | −25% к сумме за штуку | +2 дня |
| Срочно (в течение суток) | +50% к цене | — |

Обоснование верхней границы: результат идёт через FLUX.2 + LaMa с посадкой
головы по геометрии донора, а не через готовый плагин-фильтр — это медленнее
и дороже в исполнении, чем массовые дешёвые face-swap боты, и клиенту можно
показать это на примере прогона, а не на словах.

Нижняя граница — ниже неё не соглашаться без явной причины (постоянный
клиент, крупный пакет, тестовый первый заказ на новой бирже для отзыва).

## B2B — интеграция face-swap в чужой продукт (Upwork, Fiverr)

Здесь платят не за фото, а за работу разработчика — пайплайн в этом
репозитории (Node API + очередь + Python ML-сервис + GPU-инференс) уже
показывает архитектуру, которую можно предложить как основу.

| Формат | Цена | Когда предлагать |
| --- | --- | --- |
| Фиксированная цена, небольшая интеграция (API-обёртка, один endpoint) | $150–500 | Чёткое ТЗ, объём понятен заранее |
| Часовая ставка | $25–40/ч | ТЗ размытое, объём выясняется по ходу |
| Полный пайплайн под клиента (аналог этого репо: очередь, хранилище, ML-сервис) | $800–2000 | Клиент хочет production-сервис, не скрипт |

Не указывать в отклике конкретные цифры $/ч выше диапазона без запроса
клиента — сначала уточнить объём (см. `templates/upwork_fiverr.md`).

## Когда снижать, когда не снижать

- Клиент просит скидку на разовый маленький заказ → можно уступить 10–15%,
  если это первый заказ на бирже и нужен отзыв.
- Клиент просит скидку на пакет → скидка уже заложена в пакетную цену,
  дальше — только за счёт объёма (не за счёт качества и не за счёт срока).
- Клиент просит скидку и одновременно сокращает объём/срочность → предложить
  альтернативу (меньше фото, без срочности, без правок) вместо простого
  снижения цены.
- Бюджет клиента ниже нижней границы диапазона и это не пакет/не постоянный
  клиент → не браться, объяснить (или тихо пропустить, если площадка не
  предполагает обязательного ответа).
