# ml-service — ML-микросервис (Python 3.11 + FastAPI)

Замена лица на обложке: заказчик присылает своё фото, сервис возвращает обложку
с его лицом. Вызывается из Node.js API по HTTP.

Диффузия идёт на **fal.ai**; локально работают mediapipe (везёт свою модель
внутри пакета), OpenCV и сегментатор rembg. Ни компилятора C++, ни CUDA не
нужно, но **веса сегментатора занимают ~176 МБ на модель** и скачиваются при
первом вызове — см. «Вырезка головы».

Пайплайн двухшаговый: голова заказчика с причёской вырезается и вклеивается в
шаблон локально, оригинальными пикселями, а модель на очень низком `strength`
сводит только стык — контур волос и срез шеи. Подробности и причины — в разделе
«Как устроена замена лица».

> Сервис предназначен для работы с фотографиями, на использование которых
> получено согласие (заказчик книги и её получатель).

## Установка

```powershell
cd ml-service
.\scripts\setup_venv.ps1              # обычная установка
.\scripts\setup_venv.ps1 -Recreate    # пересоздать окружение
.\scripts\setup_venv.ps1 -NoDev       # без pytest/httpx/ruff
```

Linux/macOS:

```bash
./scripts/setup_venv.sh [--recreate] [--no-dev]
```

Скрипт: находит Python 3.11 → создаёт `.venv` → ставит `requirements.txt` +
dev-зависимости → копирует `.env.example` в `.env` → проверяет импорты.

Python строго 3.11 (`>=3.11,<3.12` в `pyproject.toml`) — ограничение mediapipe.

Веса сегментатора скрипт не качает: они поедут при первом заказе. Чтобы не
ждать их в бою, можно прогреть заранее (или задать `U2NET_HOME`, если кэш
хочется держать не в `~/.u2net`):

```powershell
.\.venv\Scripts\python.exe -c "from rembg import new_session; [new_session(m) for m in ('u2net_human_seg','u2net')]"
```

> `setup_venv.ps1` сохранён в UTF-8 **с BOM**: Windows PowerShell 5.1 читает `.ps1`
> без BOM как ANSI и ломается на кириллице в строках. При правке файла редактором
> сохраняйте кодировку.

### FAL_KEY

Ключ читается `fal-client` напрямую из окружения как `FAL_KEY` — **без префикса
`ML_`**, в отличие от остальных настроек. Без него `/health` по-прежнему `ok`
(процесс жив), а `/health/ready` отдаёт `503 degraded`:

```json
{
  "status": "degraded",
  "runtime": { "mediapipe": true, "opencv": true, "fal_client": true },
  "provider": {
    "model": "fal-ai/flux-kontext-lora/inpaint",
    "key_present": false,
    "key_env": "FAL_KEY"
  },
  "mask": {
    "detector": "mediapipe/face_mesh",
    "padding_ratio": 0.06,
    "feather_ratio": 0.1
  },
  "reason": "не задан FAL_KEY"
}
```

`runtime` и `provider` разделены намеренно: сразу видно, чего не хватает —
пакета или ключа.

## Как устроена замена лица

Два шага, и разделение между ними принципиальное: **внешность переносится
локально, модель работает только по стыку**.

1. **Аппликация** (`collage.py` + `segmentation.py`, локально: rembg, OpenCV,
   mediapipe) — голова заказчика вырезается целиком, вместе с причёской, и
   вклеивается в шаблон преобразованием подобия. Геометрия лица, цвет, длина и
   структура волос переносятся один в один.
2. **Сведение стыка** (`fal_api.py`, на fal.ai) — коллаж уходит в
   `fal-ai/flux-kontext-lora/inpaint` по маске из `mask_generator.py` с
   **экстремально низким strength (0.20)**. Маска открывает только внешний
   контур волос, срез шеи и следы стирания чужой причёски; лицо из неё вычтено
   явно, и модель до него не дотягивается вовсе.

Между этими шагами есть точка расширения — **мимика** (`expression.py`):
выражение лица меняется на уже вырезанной голове, до переноса в шаблон.

Оркестрация — `face_swap/pipeline.py`, единственный вход для API-слоя.

### Как сюда пришли

Схема менялась дважды, и оба раза — из-за того, что предыдущая ломала
конкретное требование.

| | одношаговая | овал лица | голова целиком |
| --- | --- | --- | --- |
| Кто переносит внешность | модель по референсу | `warpAffine` по сетке | `warpAffine` по силуэту rembg |
| Что переносится | ничего материального | только овал лица | лицо **и причёска** |
| `strength` | 0.82 | 0.22 | **0.20** |
| Что открыто модели | всё лицо | лицо + кольцо вокруг | только контур волос и шея |
| Портретное сходство | теряется | есть | есть |
| Причёска | персонажа | персонажа | **заказчика** |

Первая схема генерировала лицо практически с нуля: при `strength 0.82` похожесть
держится лишь на том, насколько модель прочитала личность с одного фото, и
черты уезжают. Вторая сходство сохранила, но оставляла заказчику волосы
нарисованного героя — на серии разворотов это выглядит как чужой человек с
подменённым лицом. Третья переносит голову целиком.

Понизить strength можно только потому, что под маской уже нужные пиксели: в
первой схеме на 0.2 просто осталось бы лицо персонажа.

### Перенос: преобразование подобия, а не аффин

По 18 опорным точкам сетки (углы глаз, спинка и крылья носа, углы рта,
подбородок, скулы, края бровей) методом наименьших квадратов считается
преобразование **подобия**: поворот, единый масштаб, сдвиг. Решение
классическое — Умеяма через SVD ковариации, `collage.similarity_transform`.

Четыре степени свободы вместо шести у полного аффина — это не экономия, а
запрет: аффин подогнал бы донора под форму чужого лица, растянув его по одной
оси, и узнаваемость исчезла бы именно на этом шаге. Матрица вида `[s·R | t]`
такого выразить не может — только повернуть лицо и поменять его размер целиком.

`cv2.estimateAffinePartial2D` считает то же самое, но через RANSAC со
случайными выборками: результат меняется от запуска к запуску, а одинаковые
входы обязаны давать одинаковый коллаж.

Уменьшение (лицо на фото почти всегда крупнее, чем на обложке) идёт в два
приёма: сначала `INTER_AREA` до нужного размера, потом поворот и сдвиг. Одним
`warpAffine` уменьшать нельзя — интерполяция выбрасывает пиксели и контуры
рвутся.

### Вырезка головы: сегментатор плюс сетка, по отдельности не работает

Контур головы с волосами по сетке mediapipe не построить — она обводит лицо и
про причёску не знает ничего. Поэтому силуэт даёт **rembg** (U²-Net), а сетка
ограничивает его головой:

1. rembg отделяет человека от фона и возвращает альфу всего силуэта — вместе с
   плечами, руками и всем остальным;
2. альфа чистится: полутень отбрасывается по порогу, а край подрезается
   эрозией — иначе вместе с волосами переезжает ореол фона фотографии;
3. по сетке строится **область головы**: эллипс, повёрнутый вместе с наклоном
   головы, с запасом на причёску сверху и по бокам;
4. снизу эллипс срезается **по линии челюсти** из той же сетки;
5. пересечение альфы с областью и есть голова. Лишние куски силуэта, попавшие в
   эллипс (поднятая рука, плечо соседа), отсекаются выбором крупнейшей связной
   компоненты.

Разделение труда здесь не случайное: **сегментатор знает, где кончаются волосы,
но не знает, где кончается голова; сетка знает, где голова, но не знает про
волосы.** Ни один из них по отдельности задачу не решает.

Пропорции эллипса — в долях размеров лица (высота = подбородок → брови):

| Параметр | Значение | Зачем |
| --- | --- | --- |
| `ML_HEAD_HAIR_RATIO` | `2.3` | вверх от подбородка. Канон даёт до макушки две высоты лица, остальное — запас на объём причёски. Мало — срежется верх волос, много — в кадр полезет фон |
| `ML_HEAD_NECK_RATIO` | `0.0` | на сколько опустить срез ниже линии челюсти. Ноль — режем ровно по ней. Больше — оставляем полосу шеи, а за ней в аппликацию лезут воротник и одежда заказчика |
| `ML_HEAD_WIDTH_RATIO` | `1.6` | ширина в долях ширины лица, запас на пышные причёски |
| `ML_HEAD_ERODE_RATIO` | `0.006` | подрезка края силуэта внутрь; 2-3 px на типичном портрете |

Эллипс поворачивается вместе с головой (угол — по линии глаз): у наклонённого
лица неповёрнутый срезал бы висок с одной стороны и захватывал фон с другой.

Низ отрезается **по дуге челюсти из сетки**, а не прямой поперёк кадра. Прямая
через подбородок оставляла бы по бокам от него два треугольника шеи — челюсть
поднимается к ушам, а линия нет; прямая ниже подбородка тянула бы за собой
воротник и плечи. Прежняя версия отступала от подбородка на `0.45` высоты лица,
и на коллаж приезжала чёрная футболка донора.

### Чистый край: порог и эрозия

U²-Net отдаёт не бинарную маску, а карту уверенности, и вокруг волос лежит
широкая полутень. Пиксели в ней наполовину состоят из фона фотографии — на
обложке это грязная кайма вокруг причёски. Поэтому альфа сначала режется
порогом (`_ALPHA_SOLID`, 160), а потом подрезается эрозией внутрь на
`ML_HEAD_ERODE_RATIO` от высоты лица: граница сегментатора идёт по внешним
пикселям прядей, и они с этим фоном уже смешаны.

Растушёвка края аппликации (`ML_COLLAGE_FEATHER_RATIO`) ведётся **внутрь**
силуэта — эрозия перед размытием. Симметричная вернула бы наружу ровно те
пиксели, которые срезали, только с половинной прозрачностью, то есть тем же
ореолом.

Модели сегментации разные для фотографии и обложки (`ML_SEG_MODEL_PHOTO`,
`ML_SEG_MODEL_COVER`): человеческая аккуратнее ведёт край волос, но
нарисованный персонаж ей не всегда знаком. Веса — ~176 МБ на модель, качаются
при первом вызове; в Docker кладутся на этапе сборки, локально видно по
`collage.weights_ready` в `/health/ready`.

### Перенос причёски: что делать с волосами персонажа

Вклеенная голова не всегда закрывает нарисованную: у героя с гривой до плеч
вокруг неё остаётся его собственная шевелюра, и на развороте оказывается два
человека сразу. Попросить модель убрать её нельзя — на `strength 0.2` она
ничего не убирает, только подкрашивает.

Поэтому тем же способом находится голова персонажа на шаблоне, и всё, что не
закрыла вклейка, стирается: дыра затягивается по окружающему фону (Telea) и
попадает в маску инпейнтинга, где модель кладёт поверх мазок. Это компромисс —
идеально восстановить фон за головой локально невозможно, — и при `erased_ratio`
выше 0.5 в лог уходит `warning`: половина головы персонажа мимо вклейки означает,
что фон придётся домысливать.

Промах сегментатора на обложке (рисованный персонаж — не тот материал, на
котором учили U²-Net) стоит предупреждения в логе, а не отказа: шаг просто
пропускается. Выключается целиком через `ML_COLLAGE_ERASE_TEMPLATE_HEAD=false`.

### Тон кожи: LAB, и только по коже

`ML_COLLAGE_COLOUR_MATCH` (`0.8`) подгоняет среднее и разброс по каналам **LAB**
под лицо шаблона. Геометрию это не трогает вовсе (поканальная кривая), но
снимает разницу между светом фотостудии и светом иллюстрации: при strength 0.2
модель не успевает свести освещение сама, и лицо остаётся фотографией на
обложке. LAB, а не BGR, потому что там яркость отделена от цвета и подгонка
тона не задевает светотеневой рисунок лица.

**Волос коррекция не касается.** Их переносят ради того, чтобы они остались
волосами заказчика; подтянуть их к палитре персонажа означало бы перекрасить
донора в нарисованного героя. Смешивание идёт в BGR, а не в LAB, ровно поэтому:
обратный перевод LAB → BGR не побитовый, и пиксели с нулевым весом уехали бы на
единицу-две просто оттого, что их прогнали через цветовое пространство.

### Маска: только стык, лица в ней нет

Смысл маски перевернулся вместе с пайплайном. Пока лицо рисовала модель, белым
отмечалось само лицо. Теперь оно приходит готовым, и инпейнтингу остаётся
граница:

1. **внешний контур волос** — кольцо вдоль силуэта вклейки, разность дилатации
   и эрозии. Полигоном такой контур не описать: у прядей он рваный;
2. **срез шеи** — полоса поперёк линии отрыва. Заметно шире кольца: оторванную
   шею не сглаживают, а закрывают — воротником, тенью, прядью;
3. **следы стирания** причёски персонажа.

Лицо защищено отдельно и явно: контур из сетки растушёвывается и **вычитается**
из маски последним действием. Черты оказываются под нулём — модели недоступны
вовсе. У самой кромки челюсти маска гасится лишь наполовину: иначе
фотографическая щека встречалась бы с живописью встык, без единого пикселя на
переход.

| Параметр | Значение | Что задаёт |
| --- | --- | --- |
| `ML_MASK_EDGE_RATIO` | `0.05` | половина ширины кольца вдоль контура волос |
| `ML_MASK_NECK_RATIO` | `0.35` | толщина полосы на срезе шеи |
| `ML_MASK_GUARD_RATIO` | `0.06` | растушёвка защиты лица |
| `ML_MASK_FEATHER_RATIO` | `0.06` | спад 255 → 0 по краям всей зоны |

Спад делается не простым размытием, а через `soften` (дилатация на `feather`,
затем размытие тем же ядром): кольцо вдоль волос узкое, и симметричный гауссиан
сбил бы его пик заметно ниже 255 — зона стыка открылась бы модели лишь частично.

Доли — от высоты лица **на шаблоне**, а не в пикселях: обложки приходят и в 4K,
и превью-размером.

### Мимика: интерфейс есть, реализации нет

Обложка — не одна картинка, а разворот за разворотом, и на каждом оказывается
одно и то же выражение лица. `expression.py` задаёт место, где это чинится:
трансформер получает вырезанную голову (кадр, альфу и сетку) **до** переноса в
шаблон. Раньше нельзя — нет вырезанного лица; позже — лицо уже вклеено, и правка
поедет вместе с фоном обложки.

Реализации пока нет намеренно. Любая переделка мимики — это изменение геометрии
лица, то есть ровно то, от чего уходили, вводя жёсткий коллаж. Сначала нужен
инструмент, сохраняющий личность (кандидаты: LivePortrait на fal, локальный варп
по сетке с ограничением смещений), и способ проверить, что заказчик остался
узнаваем.

До тех пор незнакомая эмоция получает честный `501 EXPRESSION_NOT_SUPPORTED`, а
не молча возвращённое неподвижное лицо: молчаливый отказ обнаружился бы уже на
печати тиража. Добавление трансформера — регистрация объекта, больше править
ничего не нужно:

```python
class Smile:
    name = "smile"
    def apply(self, face: expression.Face) -> expression.Face: ...

expression.register(Smile())
```

После регистрации значение сразу становится допустимым в параметре `emotion`
эндпоинта `/face-swap` и появляется в `/health/ready`.

### Модель: почему именно kontext-inpaint

`fal-ai/flux-kontext-lora/inpaint` принимает `image_url` (**коллаж**) +
`mask_url` (наша маска) + `reference_image_url` (фото заказчика). Схема вызова
осталась прежней, изменился её смысл: под маску уходит уже собранная
аппликация, а референс при strength 0.20 почти ни на что не влияет — он лишь
подсказывает модели, чью голову она обводит мазком.

Что пробовали и отвергли:

| Модель | Почему не подошла |
| --- | --- |
| `easel-ai/advanced-face-swap` | ищет лицо собственным детектором, а тот обучен на фотографиях и **на нарисованных обложках лица не находит вовсе**. Настройками не лечится |
| `fal-ai/flux-pulid` | только `prompt` + `reference_image_url`. Ни маски, ни базового изображения — генерирует картинку с нуля |
| `fal-ai/ip-adapter-face-id` | только `prompt` + `face_image_url`, маски нет. То же самое |
| `fal-ai/flux-general/inpainting` + `ip_adapters` | XLabs flux-ip-adapter переносит **стиль, а не личность**: два прогона с одним донором дали два чужих несвязанных лица |

Вывод, который стоит помнить: связки «identity-модель + инпейнтинг по маске» на
fal нет, а специализированные лицевые модели спотыкаются о рисунок раньше, чем
дело доходит до качества переноса.

### Параметры инпейнтинга

Промпт больше не просит нарисовать лицо и не описывает портрет: маска до лица
не доходит. Он говорит про границу — свести край волос с фоном, закрыть срез
шеи воротником или тенью, сохранить цвет и форму причёски. Отрицания идут прямо
в текст: `negative_prompt` эндпоинт не принимает, деть их больше некуда.

| Параметр | Значение | Было | Зачем менялось |
| --- | --- | --- | --- |
| `ML_FAL_STRENGTH` | `0.20` | `0.82` | главная ручка пайплайна. Под маской лежат оригинальные пиксели фотографии, и задача одна — не дать модели до них добраться. Рабочий диапазон **0.15–0.25**: хватает на мазок и сведение стыка, но не на изменение черт и не на перекраску волос. Выше ~0.28 (`_SAFE_STRENGTH`) плывёт контур причёски и в лог уходит `warning`; ниже 0.15 мазок не набирается и стык остаётся виден |
| `ML_FAL_GUIDANCE_SCALE` | `2.5` | `3.5` | 3.5 нужны были, чтобы перебороть фотофактуру референса. Теперь фотография — основа кадра, а не соперник; на низком strength 2.5 (дефолт эндпоинта) даёт более чистый результат, выше лезут артефакты контраста на считанных шагах денойза |
| `ML_FAL_STEPS` | `50` | `40` | реально исполняется лишь доля `strength` от шагов: 50 × 0.20 = **10 шагов денойза**. При 40 их остаётся 8, и переход по контуру волос набраться не успевает |

**`ip_adapter_scale` у эндпоинта нет.** Лишний ключ он не игнорирует, а
заворачивает весь запрос, поэтому схема аргументов зафиксирована тестами
(`tests/test_fal_api.py`) — на ней уже обжигались вживую, и выяснялось это
только после боевого прогона. Там же зафиксирован и диапазон strength: уехавший
вверх дефолт означал бы молчаливый возврат к одношаговой схеме.

Финальные значения всё равно подбираются глазами по конкретной обложке; все три
переопределяются из окружения без пересборки.

### Известные ограничения

- **Мелкое лицо на обложке.** mediapipe Face Mesh не находит лицо мельче ~20%
  ширины кадра. Лицо нужно найти в обоих кадрах, обходного пути нет — обложка в
  полный рост завернётся как `422 NO_FACE_DETECTED` (в `details.image` видно,
  какой именно кадр не подошёл).
- **Ракурс.** Перенос плоский: если на фотографии лицо в три четверти, а на
  обложке анфас, никакое двумерное преобразование их не совместит. Лечится
  только другим исходником.
- **Разрешение фотографии.** Лицо на фото должно быть не мельче, чем на
  обложке: `scale > 1` означает растягивание, и вклейка выйдет мыльной. Уходит
  в лог `warning`.
- **Причёска персонажа сильно больше донорской.** Стирание оставляет за головой
  затянутое Telea пятно, и на `strength 0.2` модель поверх него кладёт только
  мазок, а не восстанавливает фон. Признак — `erased_ratio` выше 0.5.
- **Длинные волосы.** Область головы — эллипс с фиксированными пропорциями, а
  низ отрезан по линии челюсти: всё, что ниже, в аппликацию не попадает. Коса
  до пояса перенесётся обрезанной у подбородка. Это цена чистого среза — иначе
  вместе с волосами приезжает одежда.
- **Мимика не меняется.** Точка расширения есть, трансформеров нет: любая
  эмоция, кроме `neutral`, отвечает `501`.
- **Одно лицо за запрос.** Берётся крупнейшее найденное; `faces_detected` и
  `faces_swapped` в метаданных всегда `1`.
- **Время.** Два прогона сегментатора и Telea добавляют ~13–18 с на 4K-обложке
  поверх времени инференса. Вызов и раньше шёл только из фоновой задачи.


`/face-swap/analyse` отдаёт габариты найденного лица — Node.js API использует его
для предпросмотра, чтобы не гонять платный инференс:

```json
{ "faces": [{ "bbox": { "x": 351, "y": 184, "width": 297, "height": 316 },
              "landmarks": 478 }], "count": 1 }
```

### Параметры `/face-swap`

Работают: `source`, `target`, `emotion`, `output_format` (`png` | `jpg`/`jpeg`).

`emotion` — мимика вклеиваемого лица. Пусто или `neutral` — лицо как снято;
любое другое значение сейчас отвечает `501` (см. «Мимика»). Node пробрасывает
поле как есть, через `options` в `faceSwap()`, — менять клиент не потребуется,
когда появятся трансформеры.

Форма принимает также `target_face_index`, `swap_all_faces`, `enhance`,
`style_strength` и `art_style`, но **пайплайн их игнорирует**: это остатки
контракта локального пайплайна с постобработкой на OpenCV. Оставлены, чтобы не
ломать вызовы Node.js API; ни одно из них сейчас ни на что не влияет.

### Метаданные результата

Изображение возвращается бинарно, метаданные — в заголовке `X-Swap-Meta` (JSON),
чтобы Node мог сразу сохранить файл без base64-обвязки:

```json
{"faces_detected": 1, "faces_swapped": 1,
 "model": "fal-ai/flux-kontext-lora/inpaint",
 "strength": 0.2, "guidance_scale": 2.5, "steps": 50,
 "output_format": "png", "seed": 1394872001,
 "collage": {"scale": 0.986, "rotation_deg": 0.63, "emotion": "neutral",
             "colour_match": 0.8, "segmenter": "u2net_human_seg",
             "head_fill": 0.659, "head_px": 193898,
             "face_height_target": 274.0,
             "erased_ratio": 0.074, "template_head_px": 202168}}
```

Блок `collage` — отчёт первого шага, и при жалобе «не похож» смотреть надо
сюда:

| Поле | О чём говорит |
| --- | --- |
| `scale`, `rotation_deg` | во сколько раз уменьшена и на сколько повёрнута голова. `scale > 1` — вклейка растянута и будет мыльной |
| `head_fill` | доля эллипса, занятая силуэтом. Около нуля — сегментатор промахнулся; около единицы — причёска упёрлась в границу области и могла обрезаться |
| `erased_ratio` | сколько головы персонажа пришлось стереть. Выше 0.5 — фон за ней домысливается. `null` — сегментатор не нашёл голову на обложке, шаг пропущен |
| `emotion` | какой трансформер мимики применялся |

### Ошибки

Все — единым JSON `{"error": {"code", "message", "details"}}` из
`app/core/errors.py`:

| Код | HTTP | Когда |
| --- | --- | --- |
| `INVALID_IMAGE` | 400 | файл не читается, неподдерживаемый формат, битые параметры маски или коллажа |
| `PAYLOAD_TOO_LARGE` | 413 | файл больше `ML_MAX_UPLOAD_MB` |
| `NO_FACE_DETECTED` | 422 | mediapipe не нашёл лица — на обложке или на фотографии, в `details.image` видно, где именно |
| `MASK_MISSING` | 500 | маска не построена — дефект вызывающего кода, до сети запрос не доходит |
| `EXPRESSION_NOT_SUPPORTED` | 501 | запрошена эмоция, для которой нет трансформера. Не 400: запрос корректен, возможности пока нет |
| `FAL_REQUEST_FAILED` | 502 | отказ fal: авторизация, баланс, сеть, ошибка модели, пустой ответ |
| `FAL_NOT_CONFIGURED` | 503 | не задан `FAL_KEY` |
| `SEGMENTER_UNAVAILABLE` | 503 | rembg не установлен, не смог скачать веса или не нашёл голову на фотографии |

Загрузка изображений в CDN fal обёрнута намеренно: она идёт до инференса и падает
первой, а необёрнутое httpx-исключение дошло бы до FastAPI как `500 text/plain` и
сломало бы JSON-контракт с Node.

### Ротация

`app/core/rotation.py` — `TimedRotatingFileHandler`, расширенный проверкой
размера, чтобы политика совпадала с Node (`pino-roll`):

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `ML_LOG_ROTATE_WHEN` | `midnight` | когда ротировать (`midnight`, `H`, `D`, `S`) |
| `ML_LOG_FILE_MAX_MB` | `20` | досрочная ротация по объёму |
| `ML_LOG_BACKUP_COUNT` | `14` | сколько ротированных файлов хранить |

Файл роняется по наступлению суток либо раньше при превышении объёма; имя
ротированного файла — `app.<дата>.<номер>.log`, как у Node. Индекс нужен для
нескольких ротаций по размеру за одни сутки.

Два отличия от Node — следствие устройства stdlib:

- активным всегда остаётся `app.log`, дата появляется только у ротированных
  файлов (у `pino-roll` датирован и активный файл);
- удаление старых файлов реализовано в `_prune()`: штатное опирается на схему
  имён stdlib и не находит файлы, переименованные `namer`. Сортировка идёт по
  дате и индексу из имени, а не по `mtime` — на Windows у файлов одной серии
  ротаций метки времени совпадают.

В консоль по умолчанию идёт читаемый формат; `ML_LOG_JSON=true` включает JSON и
там. Поля совпадают с Node-сервисом (`time`, `level`, `service`, `scope`,
`message`, `request_id`), поэтому логи двух сервисов грепаются одинаково:

```json
{"time": "2026-07-23T03:49:04.369Z", "level": "info", "service": "ml-service",
 "scope": "http", "message": "GET /health/ready → 503",
 "request_id": "trace-e2e-1784778544", "status_code": 503, "duration_ms": 3.84}
```

`RequestIdMiddleware` принимает `X-Request-ID` от Node.js API (или генерирует
UUID), кладёт его в `contextvar`, возвращает в заголовке ответа и пишет
access-лог со статусом и длительностью. Штатный access-лог uvicorn приглушён до
`WARNING`, чтобы не дублировать записи без `request_id`.

Произвольные поля добавляются через `extra`:

```python
log.info("маска лица построена", extra={"face_height": 316, "feather_px": 32})
```

```
    logging.py                JSON-формат, хендлеры, фильтр request_id

    collage.py                шаг 1: перенос головы подобием и жёсткая вклейка
    mask_generator.py         сетка лица и маска стыка: контур волос, шея, защита лица
    fal_api.py                шаг 2: транспорт до fal — загрузка, схема, скачивание

```

Разделение ролей: `segmentation.py` знает про силуэт и ничего про обложку;
`collage.py` отвечает за внешность и не знает про fal; `pipeline.py` решает, что
и по какой маске обрабатывается; `fal_api.py` знает только про транспорт до fal
и ничего — про смысл операции. `expression.py` не зависит ни от чего из этого:
он получает вырезанную голову и возвращает её же.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Ни сети, ни весов: клиент fal подменяется фейком, детектор лиц — общей

логов и проброс `X-Request-ID`.

Линтер — `ruff check app tests` (конфигурация в `pyproject.toml`).

### Предпросмотр аппликации без fal

Настраивается сейчас первый шаг, а второй платный и небыстрый. `collage_preview.py`
останавливается на коллаже и раскладывает стадии по файлам:

```powershell
.\.venv\Scripts\python.exe scripts\collage_preview.py --source ..\source.jpg --target ..\spread_03.png
.\.venv\Scripts\python.exe scripts\collage_preview.py --erode-ratio 0.01 --neck-ratio 0.05
```

В `outputs/collage/` окажутся сырая альфа rembg, область головы, итоговая маска,
сама аппликация на прозрачном фоне (`40_cutout.png` — то, на что смотреть в первую
очередь), коллаж, маска стыка и `meta.json`. Стадии вырезки пишутся до сборки
коллажа: если mediapipe не найдёт лицо на обложке, аппликация всё равно останется
на диске. Сеть нужна только на первую загрузку весов rembg.

## Интеграция с Node.js API

Node-сервис ходит на `http://localhost:8000` (`ML_SERVICE_URL`). Готовность этого
сервиса — готовность всего продукта: замена лица и есть его единственная работа,
поэтому Node отдаёт `503` на `/health/ready`, когда ML недоступен.

```js
const res = await fetch('http://localhost:8000/health/ready');
const ready = res.ok; // 503 → заказы принимать бессмысленно
```

Вызов долгий (облачный инференс — десятки секунд), поэтому Node дёргает
`/face-swap` только из фоновой задачи-воркера, а не из HTTP-обработчика.
