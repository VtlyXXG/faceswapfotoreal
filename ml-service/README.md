# ml-service — ML-микросервис (Python 3.11 + FastAPI)

Замена лица на развороте книги: заказчик присылает своё фото, сервис возвращает
разворот с его лицом. Вызывается из Node.js API по HTTP.

Генерация идёт на **fal.ai**; локально работает только mediapipe (везёт свою
модель внутри пакета) и OpenCV. Ни компилятора C++, ни CUDA, ни тяжёлых весов:
единственный необязательный файл — 16 МБ семантической разметки.

Рабочая схема — **специализированный фейссвоп** (`fal-ai/face-swap`): модель
лица получает шаблон и фотографию и переносит лицо сама, ничего не рисуя по
описанию. Ни промпта, ни маски, ни локальной вклейки: всё, что не лицо, эндпоинт
оставляет своим. Фотореализм здесь не выпрашивается словами — переносится
настоящее лицо. Диффузионные схемы, которые этому предшествовали, и причины их
провала — в разделе «Как устроена замена лица».

> Сервис предназначен для работы с фотографиями, на использование которых
> получено согласие (заказчик книги и её получатель).

## Установка

```powershell
cd ml-service
.\scripts\setup_venv.ps1              # обычная установка
.\scripts\setup_venv.ps1 -Recreate    # пересоздать окружение
.\scripts\setup_venv.ps1 -NoDev       # без pytest/httpx/ruff
```

Linux/macOS:

```bash
./scripts/setup_venv.sh [--recreate] [--no-dev]
```

Скрипт: находит Python 3.11 → создаёт `.venv` → ставит `requirements.txt` +
dev-зависимости → копирует `.env.example` в `.env` → проверяет импорты.

Python строго 3.11 (`>=3.11,<3.12` в `pyproject.toml`) — ограничение mediapipe.

Веса семантической разметки (~16 МБ) необязательны, но с ними маска заметно
точнее — см. «Маска головы». Скачать заранее:

```powershell
.\.venv\Scripts\python.exe -c "import urllib.request,os; d=os.path.expanduser('~/.mediapipe'); os.makedirs(d,exist_ok=True); urllib.request.urlretrieve('https://storage.googleapis.com/mediapipe-models/image_segmenter/selfie_multiclass_256x256/float32/latest/selfie_multiclass_256x256.tflite', d+'/selfie_multiclass_256x256.tflite')"
```

> `setup_venv.ps1` сохранён в UTF-8 **с BOM**: Windows PowerShell 5.1 читает `.ps1`
> без BOM как ANSI и ломается на кириллице в строках. При правке файла редактором
> сохраняйте кодировку.

## Запуск

```powershell
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --port 8000
```

Ключей и учётных записей для запуска не нужно: маски, пересадка головы и
подготовка пакета считаются локально.

Swagger: <http://localhost:8000/docs>

В составе общего стека — `docker compose up -d ml-service` из корня репозитория;
образ собирается из `Dockerfile` (python:3.11-slim + libgl/libglib для opencv).

### FAL_KEY — не нужен

Путь через fal.ai **выключен по умолчанию** (`ML_FAL_ENABLED=false`): личность
переносится своим Flux + PuLID на GPU-боксе, пересадка головы считается
локально. При выключенном пути ключ не читается вовсе, `fal-client` не входит в
обязательные зависимости, а `/health/ready` отвечает `200 ready` без каких-либо
учётных данных.

Включать осознанно — `ML_FAL_ENABLED=true`, `FAL_KEY=...` и
`pip install fal-client`. Вызов при выключенном пути возвращает `FAL_DISABLED`,
а не требование ключа: «возможность отключена» и «сервис недонастроен» — разные
состояния.

Ключ читается `fal-client` напрямую из окружения как `FAL_KEY` — **без префикса
`ML_`**, в отличие от остальных настроек. При ВКЛЮЧЁННОМ пути без него `/health`
по-прежнему `ok` (процесс жив), а `/health/ready` отдаёт `503 degraded`:

```json
{
  "status": "degraded",
  "runtime": { "mediapipe": true, "opencv": true, "fal_client": true,
               "parsing_weights": true },
  "provider": {
    "model": "fal-ai/face-swap",
    "key_present": false,
    "key_env": "FAL_KEY",
    "strategy": "face_swap",
    "identity_field": "swap_image_url",
    "needs_mask": false,
    "sends": ["base_image_url", "swap_image_url"]
  },
  "mask": {
    "detector": "mediapipe/face_mesh + selfie_multiclass",
    "dilate_ratio": 0.12, "feather_ratio": 0.1, "neck_ratio": 0.35
  },
  "reason": "не задан FAL_KEY"
}
```

`runtime` и `provider` разделены намеренно: сразу видно, чего не хватает —
пакета или ключа. Поле `sends` — ключи, которые схема положит в тело запроса:
первое, на что смотрят при 422.

## Как устроена замена лица

Рабочий путь — один шаг:

**Перенос лица** (`refine/fal_face_swap.py`, на fal.ai). Шаблон и фотография
заказчика уезжают одним вызовом — `base_image_url` и `swap_image_url`, больше
эндпоинт не принимает ничего. Специализированная модель находит лицо на шаблоне
своим детектором, переносит на него лицо с фотографии и возвращает готовый кадр.
Ни промпта, ни маски, ни постобработки: **фотореализм здесь не результат
уговоров, а свойство метода** — переносится настоящее лицо, а не рисуется
похожее.

Ответ проверяется на месте. Не найдя лица, эндпоинт **не отвечает ошибкой — он
возвращает присланный шаблон**: код 200, картинка на месте, счёт выставлен,
замены нет. Отличить это можно только сравнением с тем, что отправляли, и
пайплайн это делает: расхождение ниже порога — `422 NO_FACE_DETECTED`, а не
разворот без замены, уехавший в печать.

Локальной работы на этом пути нет вовсе, и это тоже решение, а не упущение:

- маска не строится — область эндпоинт находит сам, а её построение стоит
  3 секунд на 4K и даёт лишний повод отказать заказу (`NoFaceDetectedError` от
  НАШЕГО детектора там, где чужой справился бы);
- фотография уходит теми же байтами, что прислал заказчик — поле вокруг неё
  лечило перенос композиции у диффузии, а чужому детектору лица оно только
  мешает.

### Причёска: второй шаг там, где фейссвоп не может

У метода есть граница, и она не настраивается: **переносится лицо**. Причёска
остаётся от шаблона — эндпоинт не читает текста и волос не касается по
устройству. Донору с коротким светлым ёжиком достаётся нарисованная грива, и
внутри одношагового пути починить это нечем.

Профиль `pixar_hair` (`refine/hair_swap.py`) добавляет проход ПЕРЕД заменой лица:

1. **Маска волос** (`hair_mask.py`, локально) — по разметке выделяется причёска
   персонажа, и из области **вычитается лицо**: класс `FACE` плюс контур из
   сетки, расширенные и размытые. Но **волосы важнее защиты**: готовый вес
   гасится классом волос, поэтому чёлка на лбу и бакенбарды на щеках остаются
   внутри области. Исключение одно — **ядро лица** (глаза, нос, рот): его
   волосы не перебивают никогда.
2. **Правка причёски** — редактор получает **окно вокруг головы, текст и
   больше ничего** и меняет одни волосы. Ответ проверяется тем же приёмом, что
   и у фейссвопа, только **внутри маски**: редактор тоже умеет вернуть кадр без
   изменений (`422 HAIR_EDIT_FAILED`).
3. **Вклейка** (`composite.py`) — в шаблон возвращается ровно область причёски.
4. **Перенос лица** — тот же `fal-ai/face-swap`, той же стратегией `face_swap`
   из реестра, без единого изменения в ней.

**Фотография заказчика на первый шаг не отправляется.** Это стоило двух
прогонов: получив портрет крупным планом вторым файлом, универсальный редактор
понимает его не как «вот чья причёска», а как «вот что нарисовать», — и оба
живых редактора нарисовали лицо донора **на затылке персонажа**, в пустой
области маски волос, то есть ровно там, где им разрешили рисовать. Личность
переносит специализированная модель на втором шаге; общему редактору на первом
достаточно слов.

Поэтому схемы шага причёски — «одиночные» (`nano_banana_solo`, `seedream_solo`,
`hy_wu_solo`): в массив уезжает один шаблон. Профиль с обычной схемой **не
собирается вовсе** — такую ошибку нельзя оставлять на исполнение, потому что
она не даёт ни ошибки, ни `422`: эндпоинт отвечает успехом, и брак виден только
глазами.

Отсюда же требование к описанию: `hair` в запросе или `ML_HAIR_DESCRIPTION` на
тираж — **единственный источник** того, что рисовать. Пусто в обоих — `400` до
всякой сети, потому что «замени причёску» без описания означает случайную
причёску. Описывать надо физику: миллиметры, просвечивающую кожу головы, край
стрижки.

Три решения здесь важнее остальных.

**Порядок шагов.** Правка волос — это диффузия, и всё, что попадёт под её маску,
вернётся сглаженным. Пущенная после переноса, она прошла бы по настоящим
фотографическим пикселям лица — по тому единственному, ради чего всё делается.
Первым шагом она рискует только нарисованной головой шаблона, которую всё равно
заменят.

**Защита лица.** После первого шага кадр отличается от исходного ТОЛЬКО внутри
причёски. Это не аккуратность ради аккуратности: детектор фейссвопа ищет лицо
сам, шаблон с уже сработавшим детектором — проверенный вход, и тронутые глаза
означают риск молчаливого отказа. Побочно это же спасает от сглаженной кожи.

**Окно, а не разворот.** Первый живой прогон правку сделал — фон на месте
срезанных волос дорисовался безупречно, — но объём причёски остался шаблонным:
вместо жёсткого ёжика вышел гладкий блондинистый шлем. Дело не в силе правки:
**у этих редакторов её нет как параметра** (проверено по openapi — ни `strength`,
ни `denoising_strength`, ни `image_guidance`, ни `guidance_scale`). Дело в
масштабе: на 4K-развороте голова занимает проценты кадра, рабочий кадр редактора
около мегапикселя, и на сотню пикселей волос он отдаёт мыльную шапку — стричь
там нечего. Поэтому уезжает окно вокруг маски волос с полем в высоту лица
(`ML_HAIR_CROP_RATIO`, 0 отправляет разворот целиком), а поправленное окно
возвращается на место копией.

Второй урок того же прогона — в промпте. Фраза «same head size», написанная
против перекадрирования, читалась моделью буквально: голова **вместе с копной
волос** объявлялась неприкосновенной по размеру. Теперь череп с лицом и контур
причёски разведены прямым текстом, старая причёска названа формой на удаление, а
«короткая» описана физически — миллиметры, просвечивающая кожа головы, резкий
край стрижки.

**Почему волосы важнее защиты.** Защита лица расширяется наружу — на
`protect_ratio` во все стороны, то есть в прилегающие волосы, и на 4K это
десятки пикселей по всему периметру лица. Спасённая ею прядь не мелочь:
редактор её не сотрёт, фейссвоп вклеит лицо ПОД неё, и с висков готового
разворота свисают тёмные ошмётки прежнего героя. Поэтому пиксель, размеченный
как волосы, попадает под правку, даже если лежит на щеке. Обратная опасность —
разметка, принявшая затенённое лицо за волосы, — закрыта ядром: выпуклой
оболочкой глаз, носа и рта, то есть ровно тем, по чему детектор фейссвопа ищет
лицо. Сколько волос всё-таки осталось вне маски, видно в `hair.hair_left_px`;
заметная доля уходит в `warning`.

Ширину ядра задаёт `ML_HAIR_CORE_RATIO` — сжатие **поперёк оси лица**, вместе с
её наклоном. Нужно оно ради прядей, спускающихся от виска к щеке: оболочка
кончается на внешнем углу глаза, но дилатация уводит её ещё на `protect` в
сторону виска, и локон попадает под защиту. Сжатие безопасно по устройству, а не
по осторожности значения: дилатация круговая и возвращает накрытие наружу,
поэтому угол глаза остаётся защищённым, пока сдвиг `(1 - core) × полуширина`
меньше поля `protect × высота лица`.

**Прядь, которую разметка считает лицом.** Тонкий тёмный локон от виска к щеке
сегментатор (он работает на 256×256) растворяет в классе `FACE`, и тогда не
помогает ничего из перечисленного выше. В маску прядь не входит — маска строится
из класса волос. Гашение защиты волосами её не касается — для разметки она не
волосы. `core` жмёт **ядро**, то есть оболочку глаз, носа и рта, а класс `FACE`
остаётся во всю щёку. И расширять за ней маску бесполезно: **защита вычитается
ПОСЛЕ дилатации**, поэтому на щеке маска умножится на ноль при любом
`ML_HAIR_DILATE_RATIO` — поднимать его значит только шире размазать фон вокруг
головы, ничего не выиграв.

Остаётся сузить сам источник защиты: `ML_HAIR_GUARD_RATIO` оставляет от неё
полосу вдоль оси лица шириной `guard × полуширина` и отпускает всё, что дальше.
Полуширина меряется по самой защите, поэтому `1.0` не режет ничего. Рез идёт до
расширения и размытия — как срез по лбу, — так что ступеньки посреди щеки не
будет, а условие «пиксель на расстоянии `d` от оси свободен» читается как
`guard × полуширина + protect × высота лица < d`. Оба слагаемых замеряются на
самом кадре и приезжают в мете как `hair.guard_half_px` и `hair.protect_px` —
подбирать значение вслепую, по два вызова fal за попытку, не нужно. Ядро лица
возвращается поверх среза: глаза, нос и рот этой ручкой не открываются. Платим
щеками и висками — они уходят под диффузию, и смотреть надо на
`hair.protected_px` и на кожу щёк глазами.

**Какая из двух ручек держит остаток.** Пиксель класса волос попадает в область
по построению и после дилатации стоит в маске на 255 — уменьшить его может
только защита. Значит, у остатка ровно два виновника, и `hair.hair_left_span_px`
(поперечный вынос остатка от оси лица) вместе с `hair.guard_reach_px` (докуда
защита достаёт после среза) говорит, какой именно: остаток **ближе**
`guard_reach_px` держит `guard`, **дальше** — `core`, потому что ядро
накладывается поверх среза и дотягивается за него. Крутить их надо в разные
стороны, и раньше выбор приходилось делать наугад — по два вызова fal за догадку.

**Прядь, которой разметка не видит вовсе.** Третий случай, и здесь кончается всё,
что опирается на сегментатор. Локон от виска к щеке и дальше к воротнику не
отнесён **ни к чему**: ни к волосам, ни к лицу. Для сегментатора (256×256) его
там просто нет — а значит, `dilate` расширяет источник, которого не существует, а
`guard` и `core` только отпускают защиту, области не добавляя. Ни одно число выше
до такой пряди не дотянется по построению.

Хуже того, логи об этом молчат: `hair.hair_left_px` меряет остаток **класса**
волос, и единицы пикселей в нём прекрасно уживаются с локоном во всю щёку.
Выяснилось это дорого — прогоном со стиранием (`ML_HAIR_ERASE_RATIO`, ниже),
который залил мылом всю открытую область и оставил прядь резкой: доказательство
от противного, что под маской её не было.

Берётся она `ML_HAIR_CHEEK_RATIO` — областью, заданной **геометрией**, а не
разметкой. Два прямоугольника в осях головы (то есть вместе с её наклоном) идут
от виска вниз мимо челюсти к воротнику; поперёк они начинаются снаружи от внешних
углов глаз и уходят за ухо. Само число — докуда полоса спускается **ниже
подбородка**, в долях высоты лица; `0.35` — примерно до воротника, `0` отключает
полосу и возвращает область, построенную ровно по разметке.

Защиту лица полоса гасит наравне с настоящими волосами, и без этого она не
работала бы вовсе: класс `FACE` растянут на всю щёку, а защита вычитается **после**
дилатации — на щеке маска умножилась бы на ноль. Глаза, нос и рот при этом не
открываются ни при каком её размере: поверх накладывается ядро лица, а сама полоса
внутрь и не заходит. Платим щеками и шеей — они уходят под диффузию.

В мете три числа, и вместе они отвечают, что произошло: `hair.cheek_px` (сколько
полоса накрыла), `hair.cheek_hair_px` (сколько из этого разметка считала
волосами — почти ноль подтверждает, что полоса тут единственный способ) и
`hair.cheek_open_px` (сколько дошло до маски; заметно меньше `cheek_px` — полосу
съела защита, и вот тогда крутить `guard`).

**Стирание причёски в кадре — путь, который не сработал.** `ML_HAIR_ERASE_RATIO`
(`pipelines/erase.py`) разрушает пиксели старых волос до отправки: заливка по
цвету окружения плюс размытие поверх неё. Гипотеза была в том, что редактор
цепляется за структуру внутри открытой маски — область он не рисует с нуля, а
переписывает присланные пиксели, и тёмная линия на светлой щеке читается им как
тень скулы, то есть как лицо. Прогон гипотезу опроверг (прядь лежала вне маски) и
показал цену: вместе со структурой пропадает силуэт старой копны — единственное
указание, где вообще растут волосы, — и редактор рисует ёжик прямо по черепу,
голова выходит лысой; а границы заливки возвращают светлый ореол. По умолчанию
`0`; оставлено переключателем, как `kontext_multi`. Одно следствие пережило
эксперимент и осталось в коде навсегда: молчаливый отказ редактора ловится
сравнением ответа с тем, что **отправляли**, а не с шаблоном.

**Светлый ореол вокруг головы.** Маска волос обходит голову кольцом и там, где
лежала грива, выходит на фон. Редакторы общего назначения возвращают кадр не в
том тоне, в каком получили — поднятые тени, чуть светлее, чуть теплее, — и этот
общий увод, безобидный на целом кадре, в кольце читается как свечение вокруг
головы. Растушёвка тут не лечит и не может: она размывает **край** кольца, а
увод живёт внутри, где вес маски равен единице и пиксель копируется из генерации
как есть; мягкий край делает светлое пятно только больше похожим на ореол.
Поэтому вклейка шага причёски идёт с `match=True`: по пикселям **вне** маски, где
обе картинки изображают одну и ту же сцену, на канал считается `gain × x + bias`,
и ею правится генерация целиком. Не увёл редактор тон — получится единица со
сдвигом в ноль. В мете это `hair.composite.match_gain` / `match_bias` и
`match_before` — расхождение вне маски **до** поправки, то самое, что и
становилось ореолом.

**Где проходит стык на лбу.** Вклейка геометрию не выравнивает — `composite.py`
расхождение только измеряет. Значит, граница маски, проходящая по **открытой
коже лба**, превращает сдвиг генерации в рубец: голова читается как накладка.
Выходов два, и они противоположны. Увести границу вверх, в волосы, где ступенька
невидима (`ML_HAIR_PROTECT_RATIO` больше, `ML_HAIR_DILATE_RATIO` меньше), либо
опустить её до бровей (`ML_HAIR_FOREHEAD_RATIO=0.05`): тогда лоб целиком рисует
редактор, полосы старой кожи между лицом от фейссвопа и новой причёской не
остаётся, а стык уходит под растушёвку самого фейссвопа. Что выбрать, показывает
мета: `hair.composite.fit=cover` вместе с заметным `aspect_drift` означает, что
сдвиг наш, вклеечный, — тогда надёжнее второй путь.

Чем путь дороже: вторым вызовом, вторым счётом и одним новым поводом отказать
заказу. И он требует весов разметки — форму причёски знает только она; без них
`/health/ready` отдаёт `degraded`, но лишь при выбранном профиле.

Отвечает за это одно поле профиля — `needs_mask`. Диффузионные стратегии
включают локальную геометрию обратно вместе с собой (`refine/profiles.py`,
`StrategyDefaults`), и тогда шагов становится три:

1. **Маска головы** (`head_mask.py`, локально: mediapipe + OpenCV) — на
   ШАБЛОНЕ, а не на доноре, выделяется голова персонажа: лицо, волосы и полоса
   шеи под подбородком. Маска расширяется и растушёвывается по краю.
2. **Генерация** (`refine/kontext_multi.py`) — шаблон и фотография уезжают
   массивом `image_urls`, модель перерисовывает кадр целиком.
3. **Вклейка** (`composite.py`, локально) — из ответа по растушёванной маске
   берётся ровно голова, всё остальное остаётся **побитово** пикселями шаблона.

Этот путь — запасной, и он живой не ради истории: эндпоинт у него
**переключаемый**. Схема «промпт + массив картинок» одинакова у kontext,
`nano-banana/edit`, `seedream/v4/edit` и `hy-wu-edit`, поэтому смена модели
стоит двух переменных окружения и ни строчки кода. Нужен он там, где голова
персонажа стилизована: фейссвоп переносит фотографические пиксели как есть, и с
рендером они могут не сойтись.

Маска, таким образом, не уезжает в fal ни на одном пути: рабочему эндпоинту она
не нужна, остальные её не принимают.

Точек расширения две: **мимика** (`expression.py`) — текст, которым выражение
персонажа при необходимости переопределяется, и **стратегия**
(`refine/base.py`) — подход к генерации целиком, вместе со схемой запроса.

Оркестрация — `face_swap/pipeline.py`, единственный вход для API-слоя.

### Как сюда пришли

Схема менялась пять раз, и каждый раз — потому что предыдущая ломала конкретное
требование.

| | аппликация головы | identity-inpaint | kontext-multi | **фейссвоп** |
| --- | --- | --- | --- | --- |
| Кто переносит внешность | `warpAffine` по силуэту rembg | диффузия по референсу | диффузия по двум картинкам | **модель лица** |
| Что видит модель | — | шаблон с дырой на месте головы | весь кадр целиком | весь кадр целиком |
| Промпт | — | да | да | **нет** |
| Локальная работа | 5 проходов сведения | маска | маска + вклейка | **никакой** |
| Вызовов fal на заказ | до 5 | 1 | 1 | **1** |
| Чем кончилось | «летающая голова», поза донора | хоррор-маска или сплющенная челюсть | ком кожи на месте головы | рабочий |

Аппликация решала задачу сходства и провалилась на фотореалистичных шаблонах:
фотографические пиксели на живописи остаются фотографическими, сколько их ни
своди, — «летающая голова» и плоский свет. Но добил её не материал, а **поза**:
перенос копирует геометрию донора один в один, а на развороте герой смеётся
вполоборота с открытым ртом. Совместить фотографию анфас с такой сценой
двумерным преобразованием нельзя в принципе.

Отсюда смена знака во всём. Раньше маска **вычитала** лицо и держала strength
около 0.2, лишь бы не тронуть вклеенные пиксели. Затем лицо персонажа легло
внутрь маски, а сила поднялась к единице: под маской чужая голова, сохранять
там нечего.

Инпейнт по маске тоже провалился — и ровно на том, что маска создаёт. Внутри
неё у модели **нет контекста**: она не видит ни глаз, которые заменяет, ни
линии челюсти, ни того, как на скулу падает свет. Результат — искажённые
пропорции, артефакты по краю маски и потерянная личность.

Ширина маски при этом ничего не решала, а только меняла способ провала: широкая
(вся голова) лишала модель контекста настолько, что она рисовала балаклаву или
хоррор-маску; узкая (только кожа) заставляла вписывать чужие черты в чужой
череп — сплющенная челюсть и сменившаяся этничность.

Следующий шаг снял маску с запроса вовсе: модель получала кадр целиком, рядом с
ним фотографию, и решала задачу, имея все данные, — а право менять пиксели у неё
отбиралось потом, локальной вклейкой. Не помогло и это: **общая img2img-модель
не умеет хирургической замены лица по тексту.** Никакая формулировка не
заставляет её заменить одно лицо другим и не тронуть остальное — на месте головы
получается гладкий бесформенный ком кожи.

Отсюда и вывод, на котором остановились: задача «заменить лицо» не решается
описанием — её решает модель, обученная именно ей. Диффузия ушла из рабочего
пути целиком, а с нею промпт, маска и вклейка.

Вместе с аппликацией ушли: `collage.py`, `segmentation.py` (rembg и ~350 МБ
весов u2net), LAB-коррекция тона, стирание головы персонажа с заливкой фона,
карты ControlNet и пять зональных проходов инпейнтинга.

### Маска головы

Вся локальная работа, какая осталась, — и **на рабочем пути она не выполняется**:
маска нужна диффузионным стратегиям, а фейссвоп находит область сам. Ниже — про
них; включается это одним полем профиля `needs_mask`.

Строится маска из двух независимых источников, и это не избыточность: у каждого
своя слепая зона.

| Источник | Что даёт | Когда молчит |
| --- | --- | --- |
| `mediapipe/face_mesh` | геометрию: подбородок, ось головы, высоту лица | лицо мельче ~20% кадра |
| `selfie_multiclass` (`parsing.py`) | форму: реальный контур причёски и лица | нет файла весов |

Сетка про волосы не знает ничего, поэтому форму даёт разметка: класс FACE плюс
класс HAIR. Берутся не все пиксели этих классов, а только связанные с найденным
лицом — на развороте персонаж не один, и перерисовывать причёску соседа мы не
нанимались.

Без разметки область головы описывается эллипсом по сетке (доли `2.3` высоты
лица вверх и `1.7` ширины лица вбок) — грубее, но рабоче: маска чуть шире
головы заставит модель перерисовать немного фона, маска уже головы оставит по
краю причёску прежнего героя.

Без сетки геометрию даёт разметка: вертикальная ось и подбородок по нижней
границе класса FACE. Это прямо снимает старое ограничение — разворот в полный
рост больше не отвечает `422`.

Дальше — три доли, все от высоты лица персонажа:

| Доля | По умолчанию | Что делает |
| --- | --- | --- |
| `dilate_ratio` | `0.12` | расширение за контур головы: маска впритык оставляет по краю контур старой причёски |
| `neck_ratio` | `0.35` | полоса под подбородком: там модель сводит новую голову с шеей и воротником |
| `feather_ratio` | `0.10` | растушёвка: жёсткий край даёт видимую границу генерации ровно по своей линии |

Дилатация идёт на `dilate + feather`, чтобы спад целиком лёг снаружи: сама
голова обязана остаться под сплошными 255, иначе модель получит её
полупрозрачной и оставит от старого героя призрак.

Посмотреть на маску глазами — `test_identity.py --dry-run` в корне проекта, см.
«Тесты».

### Модель: почему фейссвоп, а не диффузия

| Эндпоинт | Что принимает | Чем кончилось |
| --- | --- | --- |
| `fal-ai/pulid`, `fal-ai/flux-pulid` | `prompt` + фото лица + `image_size` | живы, но **базовой картинки у них нет**: генерируют новый кадр с нужной личностью, а не правят наш разворот. `id_weight` и `true_cfg` этого не меняют |
| `fal-ai/ip-adapter-face-id` | `prompt` + `face_image_url` | то же самое |
| InstantID | — | отдельным эндпоинтом на fal не выставлен |
| `fal-ai/flux-general/inpainting` | маску принимает, личность — через `ip_adapters` | XLabs ip-adapter переносит **стиль**, а не личность: два прогона с одним донором дали два чужих лица |
| `fal-ai/flux-kontext-lora/inpaint` | `image_url` + `mask_url` + `reference_image_url` | единственная связка «маска + личность» — и внутри маски у модели нет контекста: широкая маска даёт хоррор-маску, узкая — сплющенную челюсть и чужую этничность |
| `fal-ai/flux-pro/kontext/max/multi` | массив `image_urls`, промпт | видит весь кадр, но хирургически заменить лицо по тексту не умеет: на месте головы ком кожи |
| `easel-ai/advanced-face-swap` | `target_image` + `face_image_0` | fal объявил устаревшим: «This endpoint is deprecated» |

Вывод, к которому это сводится: **ни одна диффузионная модель не решает задачу
«замени лицо и не тронь остальное» по текстовому описанию.** ControlNet тут тоже
не помощник — он задаёт структуру, а не личность; удалённый `inpaint_controlnet.py`
управлял позой и краями, а разваливалось всё на идентичности.

Рабочий — **`fal-ai/face-swap`**. Он не диффузия: лицо переносит обученная
именно этому модель, промпта у него нет вовсе, и всё, что не лицо, остаётся
нетронутым. Схема целиком:

```
base_image_url   swap_image_url
```

Настраивать нечего в принципе, и это не бедность схемы, а её честность:
результат зависит только от того, какие две картинки прислали. Две особенности
эндпоинта, обе учтены в коде:

- ответ приходит полем **`image`**, а не списком `images` (`fal_api._extract_image`
  понимает обе формы);
- **не найдя лица, он возвращает присланный кадр, а не ошибку.** Это ловушка:
  разворот без замены выглядит как успех. Стратегия сравнивает ответ с шаблоном
  (`composite.difference`) и отвечает `422 NO_FACE_DETECTED`, если ничего не
  изменилось.

Ограничение у этого пути ровно одно, зато существенное: **лицо на шаблоне ищет
детектор fal, обученный на фотографиях.** На рисованных лицах он их не находит.
Наш локальный MediaPipe тут не свидетель: он находит лицо там, где чужой
детектор слепнет. Поэтому фотореалистичная серия идёт сюда, а живописная
осталась на диффузии.

Если голова персонажа стилизована настолько, что фотографические пиксели с ней
не сходятся, есть запасной путь — редакторы по двум картинкам на стратегии
`kontext_multi`, с локальной вклейкой поверх. Все три проверены живыми, схемы
сверены с openapi:

| Эндпоинт | Схема | Зачем |
| --- | --- | --- |
| `fal-ai/nano-banana/edit` | `nano_banana` | лучший инструкционный редактор по нескольким картинкам |
| `fal-ai/bytedance/seedream/v4/edit` | `seedream_edit` | единственный отдаёт **4K** — для печати это разница между мягкой головой и резкой |
| `fal-ai/hy-wu-edit` | `hy_wu_edit` | заявлен именно для переноса лица, есть режим «подумать перед правкой» |

Схема запроса вынесена в данные (`profiles.PayloadSchema`), а не зашита в
стратегию: имя поля, равное `None`, означает «этого ключа у эндпоинта нет», и в
тело он не попадает вовсе. Стратегия передаёт профиль целиком и не обязана
помнить, какой эндпоинт чего не понимает, — подход меняется переменной
окружения:

```
# запасной путь: тот же редактор по двум картинкам, другая модель
ML_REFINE_STRATEGY=kontext_multi
ML_REFINE_ENDPOINT=fal-ai/nano-banana/edit
ML_REFINE_PAYLOAD=nano_banana

ML_REFINE_STRATEGY=identity_inpaint    # вернуться к инпейнту по маске
```

`ML_REFINE_STRATEGY` тянет за собой эндпоинт, схему, текст инструкции и всю
локальную работу (`profiles.StrategyDefaults`): порознь они не имеют смысла, а
перепутанные дают либо `422`, либо молча испорченный кадр — переключение на
диффузию без `needs_mask` отдало бы ей пустую маску вместо рабочей области.
Точечные `ML_REFINE_ENDPOINT` и `ML_REFINE_PAYLOAD` по-прежнему сильнее — иначе
новый эндпоинт нельзя было бы попробовать без релиза.

### Вклейка: что защищает шаблон

Только на диффузионных путях; фейссвоп возвращает готовый кадр, и трогать его
нечем и незачем.

Модель возвращает кадр целиком, и вместе с головой в нём поедут фактура ткани,
надписи и узор обоев. Шаблон нарисован художником и обязан дойти до печати без
единого изменения, поэтому из ответа берётся **ровно голова**: граница — та же
растушёванная маска, а вне её результат совпадает с шаблоном побитово.

Чего вклейка не делает: она не совмещает голову с маской. Предполагается, что
эндпоинт вернул тот же кадр в той же композиции; уехал — маска ляжет мимо новой
головы и разрежет её. Молча это не проходит, в `X-Swap-Meta` едет `composite`:

| Ключ | О чём говорит |
| --- | --- |
| `drift` | насколько генерация разошлась с шаблоном **вне** маски. Единственный признак того, что модель перекадрировала сцену; выше ~12 — результату верить нельзя |
| `scale` | во сколько раз генерацию пришлось увеличить. Эндпоинт работает около мегапикселя, разворот приходит в 4K: вклеенная голова будет мягче фона |
| `fit` | `stretch` — размеры сошлись по пропорции; `cover` — пропорция разошлась, вписывали с кропом |
| `changed_px` | сколько пикселей отличается от шаблона. Заметно больше `mask_open_px` быть не может |

### Промпт: что удерживает позу

**На рабочем пути промпта нет** — эндпоинт текста не читает, и `prompt_field` у
его схемы равен `None`. Всё дальнейшее относится к диффузионным стратегиям.

Промпт собирается из трёх частей (`profiles.RefineProfile.prompt`):

1. **инструкция стратегии** — часть подхода, а не стиля. Безмасочная адресует
   картинки по порядку и требует фотографии: «первая картинка — сцена, оставь
   её как есть: композицию, кадр, фон, тело, одежду, позу, положение и размер
   головы; вторая — портрет ребёнка, с которого берётся личность. Замени одно:
   лицо и волосы. Мимику, направление взгляда и наклон головы оставь от первой
   картинки; вторая даёт только личность и никогда не диктует кадр. Свет
   совпадает с первой картинкой: направление, тени, цветовая температура,
   контраст, глубина резкости. Результат — настоящая фотография настоящего
   ребёнка: поры кожи, отдельные волоски, фотографическое зерно»;
2. **стиль** — `pixar_real` (RAW photo, текстура кожи, мягкие тени, 85 мм) или
   `impasto` (густой мазок, фактура холста). Плюс необязательное описание сцены
   из `ML_REFINE_SCENE`;
3. **отрицания** — текстом, а не полем: `negative_prompt` эти эндпоинты не
   принимают. «Никакой живописи, никакого мазка, никакой иллюстрации, никакого
   3D-рендера, никакой пластиковой кожи, никакой второй головы».

Порядок ссылок в `image_urls` и порядок слов в инструкции обязаны совпадать:
перепутав их, получаем перерисованную по мотивам обложки фотографию заказчика —
запрос при этом проходит, и заметно это только глазами.

Живописной серии безмасочный путь не подходит: его инструкция прямым текстом
запрещает мазок, а стиль `impasto` требует обратного — в одном промпте это спор
двух половин. Поэтому профиль `impasto` остался на масочной стратегии со своей
инструкцией.

Мимика вставляется между первой и второй частями и **по умолчанию пуста**:
выражение берётся со сцены. Явное значение (`emotion=laugh`) добавляет
`override the expression: …` — оно спорит с картинкой намеренно, поэтому и
сказано прямо.

### Профили

Все гиперпараметры живут набором в `refine/profiles.py`: strength, доли маски,
вес идентичности и промпты подбираются вместе, и вразнобой не имеют смысла.

| Профиль | Стиль | Стратегия | Эндпоинт | Маска |
| --- | --- | --- | --- | --- |
| `pixar_real` | фотореализм | `face_swap` | `fal-ai/face-swap` | не строится |
| `pixar_hair` | фотореализм + причёска | `hair_swap` | `nano-banana/edit` (без фото донора), затем `fal-ai/face-swap` | волос, строит стратегия |
| `impasto` | живопись | `identity_inpaint` | `flux-kontext-lora/inpaint` | строится |

У `pixar_hair` от `pixar_real` отличается ровно одно поле — имя стратегии. Шаг
замены лица тот же самый, с тем же эндпоинтом и той же схемой: двухшаговая схема
**добавляет** проход перед ним и не трогает его. Настройки первого шага живут
отдельным набором (`HairStage`) и переключаются переменными `ML_HAIR_*` — так
`ML_REFINE_ENDPOINT` продолжает означать «эндпоинт замены лица».

Живописной серии фейссвоп не подходит вдвойне: он переносит фотографические
пиксели — ровно то, чем провалилась аппликация, — а лицо на картине его детектор
и не найдёт.

`safe_strength = 0.85` — граница снизу для масочного пути: ниже неё в лог уходит
`warning`, потому что из-под слабой генерации проступают черты прежнего героя. На
рабочем пути ни `strength`, ни `steps`, ни `guidance_scale` в тело запроса не
попадают вовсе, но в профиле сохранены: по ним работают диффузионные стратегии,
если переключиться на них одной переменной окружения, и профиль обязан
оставаться собираемым при любом переключении.

Профиль — замороженный dataclass: ничего не вызывает, ни от чего не зависит,
целиком печатается в лог и в `/health/ready`. Переопределения из окружения
собираются в `from_settings()`; пустое значение означает «взять из профиля»
(именно поэтому они объявлены как `None`, а не числами с дефолтами — иначе не
отличить «оператор поставил 0.2» от «оператор не трогал»).

### Известные ограничения

- **Чужой детектор — главный риск рабочего пути.** Лицо на шаблоне ищет модель
  fal, обученная на фотографиях. Найдёт ли она нарисованное лицо, наш MediaPipe
  не предсказывает никак: он находит лица там, где чужой детектор слепнет. На
  фотореалистичных шаблонах это работает, на живописных — нет, и настройками не
  лечится. Промах виден как `422 NO_FACE_DETECTED` с `changed` в деталях.
- **Разрешение лица.** Классические фейссвоперы работают с лицом в небольшом
  разрешении и вклеивают его обратно с масштабированием: на 4K-развороте лицо
  может выйти мягче окружения. Лечится вторым проходом реставратора
  (`fal-ai/codeformer` жив, принимает `image_url` и отдаёт `image`); в пайплайн
  он не добавлен — сперва надо увидеть, нужен ли он на нашей паре.
- **Материал.** Переносятся фотографические пиксели. На фотореалистичном шаблоне
  это ровно то, что нужно; на стилизованной голове они могут не сойтись с
  рендером — тогда запасной путь через редакторы (см. выше).
- **Причёску одношаговый путь не переносит вовсе.** Модель меняет лицо и не
  трогает волосы: донору с ёжиком достаётся причёска шаблона. Лечится профилем
  `pixar_hair` — вторым вызовом перед заменой лица (см. выше). Своя цена у него
  тоже есть: **под длинными волосами лежат фон, уши, шея и одежда, и, убирая
  их, редактор обязан дорисовать то, что они прятали**. Обойти это маской
  нельзя — нельзя убрать длинные волосы, не перерисовав закрытого ими. Сколько
  ткани задето, видно в мете (`hair.clothes_px`).
- **Причёска на 4K мягче фона.** Редактор работает около мегапикселя. Основное
  лечение — окно вокруг головы (см. выше): в нём волосы получают на порядок
  больше пикселей. Дополнительно помогает `seedream/v4/edit` — единственный
  отдаёт 4K. Масштаб вклейки виден в `hair.composite.scale`, и выше 1.5 он
  уходит в `warning`.
- **Силы правки у редакторов нет.** Ни `strength`, ни `denoising_strength`, ни
  `image_guidance`, ни `guidance_scale`, ни `negative_prompt` — схемы обоих
  живых редакторов проверены по openapi. Управляется первый шаг ровно тремя
  вещами: текстом промпта, тем, что мы отправляем (окно и его поле), и выбором
  эндпоинта. Отрицания идут словами в промпт.
- **Мимику и стиль задать нечем.** Выражение приезжает с фотографии донора;
  `emotion` на этом пути игнорируется (в лог уходит `warning`), промпта и стиля
  не существует. Управляется только тем, какое фото прислали.
- **Формат ответа выбирает эндпоинт.** `output_format` он не принимает;
  перекодировать под запрошенный мы не станем — это стоило бы той сохранности
  кадра, ради которой сюда шли. Настоящий тип уезжает в `mime_type`.

Дальше — про диффузионные пути, если на них переключиться:

- **Разрешение вклейки ограничено эндпоинтом.** Он работает около мегапикселя, а
  разворот приходит в 4K: голова из ответа увеличивается втрое-вчетверо и на
  печати будет мягче фона, который остался исходным. Видно по `composite.scale`;
  в лог от 1.5 уходит `warning`.
- **Вклейка не совмещает голову с маской.** Если модель перекадрировала сцену,
  маска ляжет мимо новой головы и разрежет её. Признак — `composite.drift`
  заметно выше нуля.
- **Мелкое лицо на шаблоне.** Face Mesh не находит лицо мельче ~20% кадра.
  Раньше это был отказ; теперь геометрию подхватывает разметка, но ось головы
  при этом считается вертикальной — сильный наклон головы персонажа развернёт
  полосу шеи мимо шеи. Видно по `mask.landmarks: false` в `X-Swap-Meta`.
- **Без весов разметки маска грубее.** Эллипс не знает ни длины волос, ни их
  формы и берётся с запасом: у персонажа с гривой до плеч модель перерисует
  часть фона. Признак — `mask.source: "ellipse"`.
- **Два персонажа рядом.** Компоненты разметки выбираются по связи с найденным
  лицом; если причёски соприкасаются, в маску попадут обе головы. Признак —
  `open_share` заметно выше обычного (в лог уходит `warning` от 0.5).
- **Одно лицо за запрос.** Берётся крупнейшее найденное; `faces_detected` и
  `faces_swapped` в метаданных всегда `1`.
- **Мимика — только из списка.** Значение вне реестра отвечает `501`; список —
  `expressions` в `/health/ready`.
- **Проброс лицевых эмбеддингов не реализован.** Считать их нечем (InsightFace
  тянет onnxruntime и свои веса), а эндпоинта, который принимает вектор вместе
  с маской, на fal нет. Появится — добавляется стратегией, без правки
  `pipeline.py`.
- **Время.** Локальная часть — 2–3 с на 4K-развороте (сетка плюс разметка), и на
  рабочем пути её нет вовсе: всё время заказа занимает инференс. Вызов идёт
  только из фоновой задачи Node.

## Эндпоинты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | liveness — процесс жив, ничего не проверяется |
| `GET` | `/health/ready` | readiness — зависимости, `503` если не готов. `FAL_KEY` спрашивается только при `ML_FAL_ENABLED=true` |
| `POST` | `/face-swap/analyse` | детекция лица (multipart `image`) |
| `POST` | `/face-swap` | замена лица, возвращает изображение + заголовок `X-Swap-Meta` |

```bash
curl http://localhost:8000/health

curl -X POST http://localhost:8000/face-swap \
  -F source=@photo.jpg -F target=@spread.png -F gender=female \
  -o result.png -D -
```

`/face-swap/analyse` отдаёт габариты найденного лица — Node.js API использует его
для предпросмотра, чтобы не гонять платный инференс:

```json
{ "faces": [{ "bbox": { "x": 351, "y": 184, "width": 297, "height": 316 },
              "landmarks": 478 }], "count": 1 }
```

### Параметры `/face-swap`

Работают: `source`, `target`, `emotion`, `hair`, `output_format`
(`png` | `jpg`/`jpeg`).

`hair` — причёска заказчика словами: `short blonde buzz cut`. Действует только
на двухшаговом пути (`pixar_hair`), и там он **обязателен**: фотография на шаг
причёски не отправляется, поэтому текст — единственный источник того, что
рисовать. На весь тираж то же самое задаётся через `ML_HAIR_DESCRIPTION`;
пусто в обоих — `400 INVALID_IMAGE` до сети.

`emotion` — мимика. **На рабочем пути не действует** (выражение приезжает с
фотографии донора; в лог уходит `warning`). На диффузионных: пусто или
`neutral` — выражение берётся с шаблона; `smile`, `laugh`, `surprise`, `calm`
переопределяют его через промпт; неизвестное значение отвечает `501`.

`output_format` фейссвоп не принимает — формат ответа он выбирает сам, и
настоящий тип приезжает в `mime_type`.

Форма принимает также `target_face_index`, `swap_all_faces`, `enhance`,
`style_strength` и `art_style`, но **пайплайн их игнорирует**: это остатки
контракта локального пайплайна с постобработкой на OpenCV. Оставлены, чтобы не
ломать вызовы Node.js API; ни одно из них сейчас ни на что не влияет.

### Метаданные результата

Изображение возвращается бинарно, метаданные — в заголовке `X-Swap-Meta` (JSON),
чтобы Node мог сразу сохранить файл без base64-обвязки:

```json
{"faces_detected": 1, "faces_swapped": 1,
 "profile": "pixar_real", "strategy": "face_swap",
 "model": "fal-ai/face-swap", "payload": "face_swap",
 "identity_field": "swap_image_url", "needs_mask": false,
 "sends": ["base_image_url", "swap_image_url"],
 "seed": 1394872001, "emotion": "neutral", "mask": null,
 "reference": {"reason": "disabled"}, "changed": 6.412,
 "image_url": "https://fal.media/files/…/out.png"}
```

`mask: null` — рабочий путь локальной геометрии не строит; `reference.reason:
"disabled"` — фотография ушла теми же байтами, что пришла. `changed` — насколько
ответ отличается от шаблона: ниже 0.35 заказ отвечает `422`, потому что это
молчаливый отказ эндпоинта, а не замена.

На диффузионных путях в мете вместо этого приезжают блоки `mask` и `composite`,
а ссылка на ответ модели зовётся `generated_url` — она ведёт на кадр **до**
вклейки, с перерисованными фоном и одеждой:

```json
{"strategy": "kontext_multi", "payload": "kontext_multi",
 "generated_url": "https://fal.media/files/…/out.png",
 "mask": {"source": "parsing", "landmarks": true, "parsing": true,
          "face_height": 250.3, "chin": [1032.0, 715.0],
          "dilate_px": 30, "feather_px": 25, "neck_px": 88,
          "open_px": 342552, "open_share": 0.0817},
 "composite": {"generated_size": [1392, 752], "template_size": [4096, 2212],
               "scale": 2.942, "fit": "stretch", "drift": 4.1,
               "mask_open_px": 342552, "changed_px": 351180}}
```

Блок `mask` — отчёт первого шага, и при странном результате смотреть надо сюда:

| Поле | О чём говорит |
| --- | --- |
| `source` | `parsing` — форма по разметке; `ellipse` — запасной путь, маска грубее |
| `landmarks` | нашлась ли сетка лица. `false` — ось головы считалась вертикальной |
| `open_share` | доля кадра, открытая модели. Заметно больше обычного — маска захватила лишнее |
| `face_height` | высота лица персонажа в пикселях: база всех долей маски |

Блок `composite` — отчёт вклейки, см. «Вклейка: что защищает шаблон».

### Ошибки

Все — единым JSON `{"error": {"code", "message", "details"}}` из
`app/core/errors.py`:

| Код | HTTP | Когда |
| --- | --- | --- |
| `INVALID_IMAGE` | 400 | файл не читается, неподдерживаемый формат, битые параметры маски или профиля, пол вне списка |
| `PAYLOAD_TOO_LARGE` | 413 | файл больше `ML_MAX_UPLOAD_MB` |
| `NO_FACE_DETECTED` | 422 | персонаж на шаблоне не найден: ни сеткой и разметкой (диффузия), ни детектором эндпоинта — тот вернул шаблон без изменений (фейссвоп) |
| `MASK_MISSING` | 500 | маска не построена — дефект вызывающего кода, до сети запрос не доходит |
| `EXPRESSION_NOT_SUPPORTED` | 501 | запрошена эмоция вне реестра. Не 400: запрос корректен, возможности пока нет |
| `REFINER_NOT_SUPPORTED` | 501 | в профиле названа незарегистрированная стратегия |
| `FAL_REQUEST_FAILED` | 502 | отказ fal: авторизация, баланс, сеть, ошибка модели, пустой ответ |
| `FAL_NOT_CONFIGURED` | 503 | путь включён, но не задан `FAL_KEY` |
| `FAL_DISABLED` | 503 | путь через fal выключен (`ML_FAL_ENABLED=false`) — штатное состояние свежего клона |

Загрузка изображений в CDN fal обёрнута намеренно: она идёт до инференса и падает
первой, а необёрнутое httpx-исключение дошло бы до FastAPI как `500 text/plain` и
сломало бы JSON-контракт с Node.

## Конфигурация

Все настройки — из ENV с префиксом `ML_` (кроме `FAL_KEY`), единственное место
чтения — `app/config.py`. Полный список с комментариями — в `.env.example`.

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `ML_FAL_ENABLED` | `false` | разрешён ли путь через fal.ai. Выключен — ключ не читается |
| `FAL_KEY` | — | ключ fal.ai, **без префикса** `ML_`. Нужен только при `ML_FAL_ENABLED=true` |
| `ML_PARSING_MODEL` | пусто | путь к весам разметки; пусто — `~/.mediapipe` или `$MEDIAPIPE_HOME` |
| `ML_MASK_DILATE_RATIO` | из профиля | расширение маски за контур головы |
| `ML_MASK_FEATHER_RATIO` | из профиля | растушёвка краёв маски |
| `ML_MASK_NECK_RATIO` | из профиля | глубина захвата шеи под подбородком |
| `ML_REFINE_PROFILE` | `pixar_real` | набор гиперпараметров: `pixar_real`, `pixar_hair`, `impasto` |
| `ML_REFINE_STRATEGY` | из профиля | подход: `face_swap`, `hair_swap`, `kontext_multi`, `identity_inpaint`. Тянет за собой эндпоинт, схему, промпт и локальную работу |
| `ML_REFINE_ENDPOINT` | из профиля | эндпоинт инференса; сильнее умолчания стратегии |
| `ML_REFINE_PAYLOAD` | из профиля | схема запроса: `face_swap`, `nano_banana`, `seedream_edit`, `hy_wu_edit` (и их `*_solo` — без фото донора), `kontext_multi`, `kontext_inpaint`, `flux_general` |
| `ML_REFINE_STYLE` | из профиля | стиль сцены в промпте; только диффузия |
| `ML_REFINE_SCENE` | пусто | описание сцены — дополнение к промпту стиля |
| `ML_REFINE_STRENGTH` | из профиля | сила генерации под маской; только `identity_inpaint` |
| `ML_REFINE_GUIDANCE_SCALE` | из профиля | строгость исполнения промпта; только диффузия |
| `ML_REFINE_STEPS` | из профиля | шагов инференса; только `identity_inpaint` |
| `ML_REFINE_IDENTITY_FIELD` | из профиля | где эндпоинт ждёт референс личности; только `identity_inpaint` |
| `ML_REFINE_IDENTITY_SCALE` | из профиля | вес референса (только для схем со списком) |
| `ML_HAIR_ENDPOINT` | `nano-banana/edit` | редактор шага причёски; только `hair_swap` |
| `ML_HAIR_PAYLOAD` | `nano_banana_solo` | схема шага причёски; только «одиночные» `*_solo` |
| `ML_HAIR_DESCRIPTION` | пусто | причёска словами — единственный источник для первого шага |
| `ML_HAIR_DILATE_RATIO` | `0.10` | расширение маски за контур волос |
| `ML_HAIR_FEATHER_RATIO` | `0.07` | растушёвка края вклейки причёски |
| `ML_HAIR_PROTECT_RATIO` | `0.05` | поле защиты вокруг лица: ширина мягкого перехода между диффузией и глазами |
| `ML_HAIR_FOREHEAD_RATIO` | `0.5` | докуда маска спускается по лбу, в долях высоты лица над бровями; `0` — до бровей, и рубца на лбу нет |
| `ML_HAIR_CORE_RATIO` | `1.0` | сжатие ядра лица поперёк оси; меньше — сильнее открыты виски и скулы, где застревают пряди |
| `ML_HAIR_GUARD_RATIO` | `1.0` | какую долю полуширины защиты лица оставить; единственная ручка против пряди, которую разметка отнесла к классу лица |
| `ML_HAIR_CHEEK_RATIO` | `0.35` | полоса вдоль щёк ниже подбородка: область по геометрии, а не по разметке; единственное, чем берётся локон, которого сегментатор не видит вовсе; `0` — выключена |
| `ML_HAIR_ERASE_RATIO` | `0` | стирание старой причёски в кадре до отправки; **провалившийся путь**, оставлен переключателем: задачи не решил, а голову оставил лысой и вернул ореол |
| `ML_HAIR_CROP_RATIO` | `1.0` | поле вокруг маски волос: редактору уезжает окно с головой; `0` — разворот целиком |
| `ML_HAIR_MIN_CHANGED` | `3.0` | порог «правка состоялась», уровни 0..255 внутри маски |
| `ML_FAL_TIMEOUT_S` | `600` | таймаут скачивания результата |
| `ML_MAX_UPLOAD_MB` | `40` | лимит на файл: 4K-развороты занимают 25–30 МБ |
| `ML_ALLOWED_ORIGINS` | `http://localhost:3000` | CORS, через запятую |
| `MEDIAPIPE_HOME` | `~/.mediapipe` | где искать веса разметки, **без префикса** `ML_` |

## Логирование и трассировка

JSON-логи пишутся в `logs/`:

| Файл | Содержимое |
| --- | --- |
| `logs/app.log` | активный файл: все записи, включая логи uvicorn |
| `logs/error.log` | активный файл: только `error` и выше |
| `logs/app.2026-07-23.1.log` | ротированные файлы |

Числа заказа идут через `extra={...}` и печатаются рядом с сообщением в обоих
форматах консоли: профиль и его гиперпараметры — строкой «генерация головы по
референсу», отчёт маски — строкой «маска головы на шаблоне построена», отчёт
вклейки — строкой «голова вклеена в шаблон».

### Ротация

`app/core/rotation.py` — `TimedRotatingFileHandler`, расширенный проверкой
размера, чтобы политика совпадала с Node (`pino-roll`):

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `ML_LOG_ROTATE_WHEN` | `midnight` | когда ротировать (`midnight`, `H`, `D`, `S`) |
| `ML_LOG_FILE_MAX_MB` | `20` | досрочная ротация по объёму |
| `ML_LOG_BACKUP_COUNT` | `14` | сколько ротированных файлов хранить |

Файл роняется по наступлению суток либо раньше при превышении объёма; имя
ротированного файла — `app.<дата>.<номер>.log`, как у Node. Индекс нужен для
нескольких ротаций по размеру за одни сутки.

Два отличия от Node — следствие устройства stdlib:

- активным всегда остаётся `app.log`, дата появляется только у ротированных
  файлов (у `pino-roll` датирован и активный файл);
- удаление старых файлов реализовано в `_prune()`: штатное опирается на схему
  имён stdlib и не находит файлы, переименованные `namer`. Сортировка идёт по
  дате и индексу из имени, а не по `mtime` — на Windows у файлов одной серии
  ротаций метки времени совпадают.

В консоль по умолчанию идёт читаемый формат; `ML_LOG_JSON=true` включает JSON и
там. Поля совпадают с Node-сервисом (`time`, `level`, `service`, `scope`,
`message`, `request_id`), поэтому логи двух сервисов грепаются одинаково:

```json
{"time": "2026-07-23T03:49:04.369Z", "level": "info", "service": "ml-service",
 "scope": "http", "message": "GET /health/ready → 503",
 "request_id": "trace-e2e-1784778544", "status_code": 503, "duration_ms": 3.84}
```

`RequestIdMiddleware` принимает `X-Request-ID` от Node.js API (или генерирует
UUID), кладёт его в `contextvar`, возвращает в заголовке ответа и пишет
access-лог со статусом и длительностью. Штатный access-лог uvicorn приглушён до
`WARNING`, чтобы не дублировать записи без `request_id`.

Произвольные поля добавляются через `extra`:

```python
log.info("маска головы построена", extra={"face_height": 316, "feather_px": 32})
```

Разделение ролей: `head_mask.py` знает про геометрию шаблона и ничего про fal;
`composite.py` знает только про два изображения и маску между ними;
`pipeline.py` решает, что и по какой маске обрабатывается; `refine/` знает, чем
и с какими числами выполняется второй шаг; `fal_api.py` знает только про
транспорт и ничего — про смысл операции. Числа при этом отделены от кода:
`profiles.py` не делает ни одного вызова, а стратегия не содержит ни одной
константы, включая имена полей запроса.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Ни сети, ни весов: клиент fal подменяется фейком, детектор лиц — общей
заглушкой из 468 точек (`tests/conftest.py`), разметка — синтетическими
масками. Проверяются главные гарантии пайплайна — лицо персонажа лежит **внутри**
маски, причёска берётся из разметки целиком, сосед по развороту остаётся
нетронутым, оба источника геометрии работают поодиночке, вне маски шаблон
переживает вклейку **побитово**, — плюс профили и их проверка до сети,
переключение стратегии по имени, схема аргументов эндпоинта (включая
отсутствие ключей, которых он не принимает), обработка ошибок транспорта,
ротация логов и проброс `X-Request-ID`.

Линтер — `ruff check app tests` (конфигурация в `pyproject.toml`).

### Прогон на живых файлах без fal

Маска считается локально и бесплатно, генерация стоит денег и минут. Смотреть на
них надо порознь — `test_identity.py` в корне проекта:

```powershell
# только маска: ключ не нужен, сеть не нужна
ml-service\.venv\Scripts\python.exe test_identity.py --dry-run

# полный прогон
$env:FAL_KEY = "..."
ml-service\.venv\Scripts\python.exe test_identity.py --target spread_03.png --source photo.jpg

# запасной путь: редактор по двум картинкам вместо фейссвопа
ml-service\.venv\Scripts\python.exe test_identity.py --strategy kontext_multi `
    --endpoint fal-ai/nano-banana/edit --payload nano_banana
```

Скрипт печатает профиль, отчёт маски, референс и **тело запроса целиком**, а в
`ml-service/outputs/` кладёт маску и наложение красным поверх шаблона. Маска
считается всегда, даже когда стратегия ею не пользуется: это единственная
местная проверка того, что лицо на шаблоне вообще различимо, — но говорит она за
НАШ детектор, а не за чужой. Ключи `--strategy`, `--endpoint`, `--payload`,
`--style`, `--strength`, `--dilate`, `--feather`, `--neck`, `--emotion`
подбирают параметры без правки `.env`; `--crop x,y,w,h` вырезает панель из
эталонного листа `SHEET_*.png`.

## Интеграция с Node.js API

Node-сервис ходит на `http://localhost:8000` (`ML_SERVICE_URL`). Готовность этого
сервиса — готовность всего продукта: замена лица и есть его единственная работа,
поэтому Node отдаёт `503` на `/health/ready`, когда ML недоступен.

```js
const res = await fetch('http://localhost:8000/health/ready');
const ready = res.ok; // 503 → заказы принимать бессмысленно
```

Вызов долгий (облачный инференс — десятки секунд), поэтому Node дёргает
`/face-swap` только из фоновой задачи-воркера, а не из HTTP-обработчика.
