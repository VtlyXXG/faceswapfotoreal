# ml-service — ML-микросервис (Python 3.11 + FastAPI)

Замена лица на обложке: заказчик присылает своё фото, сервис возвращает обложку
с его лицом. Вызывается из Node.js API по HTTP.

Диффузия идёт на **fal.ai**; локально работают mediapipe (везёт свою модель
внутри пакета), OpenCV и сегментатор rembg. Ни компилятора C++, ни CUDA не
нужно, но **веса сегментатора занимают ~176 МБ на модель** и скачиваются при
первом вызове — см. «Вырезка головы».

Пайплайн двухшаговый: голова заказчика с причёской вырезается и вклеивается в
шаблон локально, оригинальными пикселями, а модель на очень низком `strength`
сводит только стык — контур волос и срез шеи. Подробности и причины — в разделе
«Как устроена замена лица».

> Сервис предназначен для работы с фотографиями, на использование которых
> получено согласие (заказчик книги и её получатель).

## Установка

```powershell
cd ml-service
.\scripts\setup_venv.ps1              # обычная установка
.\scripts\setup_venv.ps1 -Recreate    # пересоздать окружение
.\scripts\setup_venv.ps1 -NoDev       # без pytest/httpx/ruff
```

Linux/macOS:

```bash
./scripts/setup_venv.sh [--recreate] [--no-dev]
```

Скрипт: находит Python 3.11 → создаёт `.venv` → ставит `requirements.txt` +
dev-зависимости → копирует `.env.example` в `.env` → проверяет импорты.

Python строго 3.11 (`>=3.11,<3.12` в `pyproject.toml`) — ограничение mediapipe.

Веса сегментатора скрипт не качает: они поедут при первом заказе. Чтобы не
ждать их в бою, можно прогреть заранее (или задать `U2NET_HOME`, если кэш
хочется держать не в `~/.u2net`):

```powershell
.\.venv\Scripts\python.exe -c "from rembg import new_session; [new_session(m) for m in ('u2net_human_seg','u2net')]"
```

> `setup_venv.ps1` сохранён в UTF-8 **с BOM**: Windows PowerShell 5.1 читает `.ps1`
> без BOM как ANSI и ломается на кириллице в строках. При правке файла редактором
> сохраняйте кодировку.

### FAL_KEY

Ключ читается `fal-client` напрямую из окружения как `FAL_KEY` — **без префикса
`ML_`**, в отличие от остальных настроек. Без него `/health` по-прежнему `ok`
(процесс жив), а `/health/ready` отдаёт `503 degraded`:

```json
{

  "runtime": { "mediapipe": true, "opencv": true, "fal_client": true },
  "provider": {

  "mask": {

```

пакета или ключа.

## Как устроена замена лица

Два шага, и разделение между ними принципиальное: **внешность переносится
локально, модель работает только по стыку**.

1. **Аппликация** (`collage.py` + `segmentation.py`, локально: rembg, OpenCV,
   mediapipe) — голова заказчика вырезается целиком, вместе с причёской, и
   вклеивается в шаблон преобразованием подобия. Геометрия лица, цвет, длина и
   структура волос переносятся один в один.
2. **Стилизация** (`refine/`, на fal.ai) — коллаж уходит в инпейнтинг по
   градиентной маске из `mask_generator.py`. Маска открывает внешний контур
   волос, срез шеи и следы стирания чужой причёски; лицо из неё вычтено явно, и
   модель до него не дотягивается вовсе. Чем именно выполняется шаг и с какими
   числами — задаёт **профиль** (`refine/profiles.py`).

Между этими шагами есть точка расширения — **мимика** (`expression.py`):
выражение лица меняется на уже вырезанной голове, до переноса в шаблон. У
второго шага точка расширения своя — **стратегия** (`refine/base.py`): подход к
стилизации меняется целиком, вместе со схемой запроса.

Оркестрация — `face_swap/pipeline.py`, единственный вход для API-слоя.

### Как сюда пришли

Схема менялась дважды, и оба раза — из-за того, что предыдущая ломала
конкретное требование.

| | одношаговая | овал лица | голова целиком |
| --- | --- | --- | --- |
| Кто переносит внешность | модель по референсу | `warpAffine` по сетке | `warpAffine` по силуэту rembg |
| Что переносится | ничего материального | только овал лица | лицо **и причёска** |
| `strength` | 0.82 | 0.22 | **0.20 → 0.26** |
| Что открыто модели | всё лицо | лицо + кольцо вокруг | только контур волос и шея |
| Портретное сходство | теряется | есть | есть |
| Причёска | персонажа | персонажа | **заказчика** |

Последний столбец с тех пор разделился. Пока модель только сводила шов, хватало
`strength 0.20` с маской-плато (профиль `seam`). Рабочий режим — `blend`:
маска стала градиентной, зона накрыла шею и контур волос целиком, а сила
поднялась до 0.26 — верха безопасного диапазона, за которым геометрию причёски
удерживать нечем. Профили на 0.50 (`stylise`, `stylise_controlnet`) остались
доступны, но требуют ControlNet и, значит, другого эндпоинта. Подробности — в
разделе «Второй шаг».

Первая схема генерировала лицо практически с нуля: при `strength 0.82` похожесть
держится лишь на том, насколько модель прочитала личность с одного фото, и
черты уезжают. Вторая сходство сохранила, но оставляла заказчику волосы
нарисованного героя — на серии разворотов это выглядит как чужой человек с
подменённым лицом. Третья переносит голову целиком.

Понизить strength можно только потому, что под маской уже нужные пиксели: в
первой схеме на 0.2 просто осталось бы лицо персонажа.

### Перенос: преобразование подобия, а не аффин

По 18 опорным точкам сетки (углы глаз, спинка и крылья носа, углы рта,
подбородок, скулы, края бровей) методом наименьших квадратов считается
преобразование **подобия**: поворот, единый масштаб, сдвиг. Решение
классическое — Умеяма через SVD ковариации, `collage.similarity_transform`.

Четыре степени свободы вместо шести у полного аффина — это не экономия, а
запрет: аффин подогнал бы донора под форму чужого лица, растянув его по одной
оси, и узнаваемость исчезла бы именно на этом шаге. Матрица вида `[s·R | t]`
такого выразить не может — только повернуть лицо и поменять его размер целиком.

#### Масштаб: только лицо, никакой причёски

Все 18 опорных точек — лицевые, и габаритов головы среди них нет ни одного:
масштаб не может «увидеть» причёску даже теоретически. Замер по нашим
разворотам: после переноса контур лица донора совпадает с контуром лица
персонажа с точностью **0.95x / 1.05y**.

Мерок при этом несколько, и на рисованном лице они спорят между собой — у
персонажа глаза вдвое больше человеческих, а лицо короче. Разброс на всех
десяти разворотах 114–125%:

| Разворот | лицо шаблона | umeyama | eyes | cheeks | jaw | face_height |
| --- | --- | --- | --- | --- | --- | --- |
| `spread_03` | 314 px | **1.14** | 1.33 | 1.20 | 1.17 | 1.07 |
| `spread_05` | 207 px | **0.74** | 0.87 | 0.78 | 0.73 | 0.71 |
| `spread_08` | 395 px | **1.43** | 1.64 | 1.48 | 1.44 | 1.35 |

Отсюда практический вывод: **глаза дают самый крупный масштаб** (+12…17% к
`umeyama`), высота лица — самый мелкий. Если голова кажется великоватой,
переключаться надо на `face_height`, а не на зрачки. Выбор — в
`ML_HEAD_SCALE_MARK`; значения всех мерок уезжают в `X-Swap-Meta` как
`collage.scale_marks`, чтобы на конкретном заказе было видно, откуда взялся
размер.

#### Якорь шеи: голова не должна висеть в воздухе

Совместить одним преобразованием подобия и лицо, и низ шеи невозможно: длина
шеи на фотографии своя, у персонажа своя. Лицо важнее — по нему считается
матрица, — а низ шеи после этого оказывается где придётся. Если он оказался выше
воротника, между шеей и телом остаётся зазор.

Поэтому после переноса вклейка опускается вдоль оси лица шаблона ровно
настолько, чтобы шея дошла до воротника. Только вниз (перекрытие — это и есть
нужный нахлёст), не больше `_ANCHOR_MAX_RATIO` высоты лица (иначе лицо уедет
ниже, чем его нарисовал художник) и **только если воротник персонажа реально
найден** — по догадке лицо заказчика по холсту не двигают. Величина видна как
`collage.anchor_px`.

Низ вклейки меряется **по самой альфе**, а не по расчётному отрезку среза, и это
не мелочь: разница стоила боевого прогона. Когда линия одежды донора не нашлась и
взят запасной отступ (`neck_source: fallback`), отрезок среза оказывается на 0.55
высоты лица ниже подбородка независимо от того, есть ли там пиксели. Якорь мерил
эту обещанную длину, считал, что шея уже достала до воротника, и не двигал
ничего — а на обложке висела голова с коротким обрубком шеи. По альфе такого не
случается: где вклейка кончается, там она и кончается.

#### Множитель размера головы

`ML_HEAD_SCALE_MULTIPLIER` (по умолчанию `1.0`) домножает посчитанный масштаб.
Ручка **художественная, а не геометрическая**: единица означает, что лицо донора
точно совпадает с лицом персонажа, и это верно — но у мультяшной серии лицо
занимает малую часть головы, а у фотографии большую, и «верно» читается как
большая голова на маленьком туловище. `0.85` заметно уменьшает голову, сохраняя
пропорции самого лица.

Подбирается на серию обложек, а не на заказ, и композируется с якорем сама
собой: уменьшенная голова отрывается от воротника, и якорь добирает возникший
зазор. Замер на `spread_05`:

| Множитель | scale | вклейка / голова персонажа | якорь |
| --- | --- | --- | --- |
| `1.0` | 0.744 | x0.58 | 0 px |
| `0.85` | 0.632 | x0.41 | 12 px |
| `0.7` | 0.521 | x0.28 | 39 px |

`cv2.estimateAffinePartial2D` считает то же самое, но через RANSAC со
случайными выборками: результат меняется от запуска к запуску, а одинаковые
входы обязаны давать одинаковый коллаж.

Уменьшение (лицо на фото почти всегда крупнее, чем на обложке) идёт в два
приёма: сначала `INTER_AREA` до нужного размера, потом поворот и сдвиг. Одним
`warpAffine` уменьшать нельзя — интерполяция выбрасывает пиксели и контуры
рвутся.

### Вырезка головы: сегментатор плюс сетка, по отдельности не работает

Контур головы с волосами по сетке mediapipe не построить — она обводит лицо и
про причёску не знает ничего. Поэтому силуэт даёт **rembg** (U²-Net), а сетка
ограничивает его головой:

1. rembg отделяет человека от фона и возвращает альфу всего силуэта — вместе с
   плечами, руками и всем остальным;
2. альфа чистится: полутень отбрасывается по порогу, а край подрезается
   эрозией — иначе вместе с волосами переезжает ореол фона фотографии;
3. по сетке строится **область головы**: эллипс, повёрнутый вместе с наклоном
   головы, с запасом на причёску сверху и по бокам;
4. снизу эллипс срезается **по дуге челюсти** из той же сетки, а под ней
   добавляется **колонна шеи** — до линии одежды донора;
5. пересечение альфы с областью и есть голова. Лишние куски силуэта, попавшие в
   эллипс (поднятая рука, плечо соседа), отсекаются выбором крупнейшей связной
   компоненты.

Разделение труда здесь не случайное: **сегментатор знает, где кончаются волосы,
но не знает, где кончается голова; сетка знает, где голова, но не знает про
волосы.** Ни один из них по отдельности задачу не решает.

Пропорции эллипса — в долях размеров лица (высота = подбородок → брови):

| Параметр | Значение | Зачем |
| --- | --- | --- |
| `ML_HEAD_HAIR_RATIO` | `2.3` | вверх от подбородка. Канон даёт до макушки две высоты лица, остальное — запас на объём причёски. Мало — срежется верх волос, много — в кадр полезет фон |
| `ML_HEAD_NECK_RATIO` | пусто | докуда опускается колонна шеи, доля высоты лица. Пусто — искать линию одежды по цвету; число отключает поиск и режет вслепую |
| `ML_HEAD_WIDTH_RATIO` | `1.6` | ширина в долях ширины лица, запас на пышные причёски |
| `ML_HEAD_SCALE_MARK` | `umeyama` | по какой мерке лица считать масштаб: `eyes`, `cheeks`, `jaw`, `face_height`, `median` |
| `ML_HEAD_SCALE_MULTIPLIER` | `1.0` | художественный множитель размера головы; `0.85` для мультяшных серий |
| `ML_HEAD_ANCHOR_NECK` | `true` | опускать вклейку до воротника, если шея не дотянулась |
| `ML_HEAD_ERODE_RATIO` | `0.006` | подрезка края силуэта внутрь; 2-3 px на типичном портрете |

Эллипс поворачивается вместе с головой (угол — по линии глаз): у наклонённого
лица неповёрнутый срезал бы висок с одной стороны и захватывал фон с другой.

### Шея: до линии одежды, а не по челюсти

Сначала резали по челюсти — чисто, но голова садилась на обложку **без шеи и
висела в воздухе**, и вести переход тона от кожи к телу персонажа было негде.
Теперь берётся и шея, до линии одежды донора, чтобы она легла на воротник
персонажа внахлёст.

Область поэтому собирается из двух частей: голова — эллипс, срезанный по дуге
челюсти; шея — колонна под ней. Дуга обязательна: плечи лежат на той же высоте,
что и подбородок, и прямой срез во всю ширину эллипса забирает их вместе с
воротником — на обложку приезжают два оранжевых угла футболки.

Колонна — эллипс со срезанным низом, а не прямоугольник. Прямоугольник давал по
бокам шеи две вертикальные прямые во всю её длину; на живописи такая линия
читается как наклейка, и мягким инпейнтингом её не убрать. Ширина берётся от
углов нижней челюсти (точки 172 и 397) — другой мерки шеи в сетке нет.

**Линия одежды ищется по цвету.** От подбородка вниз идёт кожа, воротник —
первое, что на неё не похоже; сравниваются только каналы `a` и `b` LAB, потому
что тень под подбородком гасит яркость вдвое, а хрому кожи держит. Короткие
разрывы перешагиваются — иначе срез встал бы на этой самой тени, вплотную к
подбородку.

По силуэту эту линию не найти, и это проверено на живом кадре: сегментатор не
отличает шею от футболки, а сужения силуэта на шее может не быть вовсе — плечи
начинаются на той же высоте, и полоса переднего плана тянется через них до края
кадра. Ширина силуэта под подбородком в нашем тестовом фото не падает, а растёт:
346 → 431 → 477 пикселей.

Что делает алгоритм, когда кожи не видно: кадр обрезан под подбородком — берёт
сколько есть (`neck_source: skin` и малое значение), свитер под горло — упирается
в нижнюю границу, мерить вовсе нечего — берёт запасные `0.55`
(`neck_source: fallback`). Отказывать нельзя ни в одном случае: фотографии
присылают заказчики. Найденное значение видно в `X-Swap-Meta` как
`collage.neck_ratio` и `collage.neck_source`.

### Чистый край: порог и эрозия

U²-Net отдаёт не бинарную маску, а карту уверенности, и вокруг волос лежит
широкая полутень. Пиксели в ней наполовину состоят из фона фотографии — на
обложке это грязная кайма вокруг причёски. Поэтому альфа сначала режется
порогом (`_ALPHA_SOLID`, 160), а потом подрезается эрозией внутрь на
`ML_HEAD_ERODE_RATIO` от высоты лица: граница сегментатора идёт по внешним
пикселям прядей, и они с этим фоном уже смешаны.

Растушёвка края аппликации (`ML_COLLAGE_FEATHER_RATIO`) ведётся **внутрь**
силуэта — эрозия перед размытием. Симметричная вернула бы наружу ровно те
пиксели, которые срезали, только с половинной прозрачностью, то есть тем же
ореолом.

Модели сегментации разные для фотографии и обложки (`ML_SEG_MODEL_PHOTO`,
`ML_SEG_MODEL_COVER`): человеческая аккуратнее ведёт край волос, но
нарисованный персонаж ей не всегда знаком. Веса — ~176 МБ на модель, качаются
при первом вызове; в Docker кладутся на этапе сборки, локально видно по
`collage.weights_ready` в `/health/ready`.

### Перенос причёски: что делать с волосами персонажа

Вклеенная голова не всегда закрывает нарисованную: у героя с гривой до плеч
вокруг неё остаётся его собственная шевелюра, и на развороте оказывается два
человека сразу. Попросить модель убрать её нельзя — на `strength 0.2` она
ничего не убирает, только подкрашивает.

Поэтому тем же способом находится голова персонажа на шаблоне и стирается —
**целиком**, а не только торчащей частью. Разница здесь не косметическая.
Стирали только торчащее — дыра выходила кольцом, и её внутренней границей были
тёмные волосы самого персонажа. Любой локальный метод восстановления тянет цвет
от границы внутрь, поэтому ровно эти волосы и размазывались обратно тёмным
ореолом вокруг вклейки. Середину всё равно закрывает вклеенная голова, так что
стирать её ничего не стоит.

Второй источник грязи — шея и уши персонажа. Заливка берёт цвет с границы дыры,
а там его кожа: на месте ушей проступали розовые пятна. Поэтому **персонаж
целиком объявляется запрещённым источником цвета**: заливка сэмплирует только
настоящий фон, а записывается всё равно только в дыру — руки, одежда и всё ниже
воротника остаются нетронутыми.

Срез области стирания — прямой на уровне подбородка, а не по дуге челюсти, как
у донорской вырезки. Дуга поднимается к ушам и оставляет их кончики; опустить её
настолько, чтобы достать, — вместе с ними сотрётся шея персонажа под
подбородком. А она нужна: вклеенная голова обрезана по челюсти, своей шеи у неё
нет, и садится она ровно на нарисованную.

| Способ | Δ к окружающему фону | Время на 4K |
| --- | --- | --- |
| `pyramid` (по умолчанию) | 2.9 | 1.5 с |
| `telea` | 1.7 | 19.5 с |
| `ns` (Навье–Стокс) | 3.2 | 26.9 с |

Замер — на `spread_03.png`, отклонение среднего цвета видимой полосы от фона
вокруг, из 255. По чистоте все три сравнимы, поэтому по умолчанию стоит
`pyramid`: заливка пирамидой (push-pull) по построению не может дать ни штриха,
ни кольца — на верхних уровнях дыра растворяется в окрестности, — а дыра здесь
размером с голову, и `cv2.inpaint` на ней стоит два десятка секунд. Меняется
через `ML_COLLAGE_ERASE_METHOD`.

При `erased_ratio` выше 0.5 в лог уходит `warning`: половина головы персонажа
мимо вклейки означает, что фон придётся домысливать.

Промах сегментатора на обложке (рисованный персонаж — не тот материал, на
котором учили U²-Net) стоит предупреждения в логе, а не отказа: шаг просто
пропускается. Выключается целиком через `ML_COLLAGE_ERASE_TEMPLATE_HEAD=false`.

### Стык по линии одежды, а не по горлу

Шея донора берётся целиком, а нарисованная шея персонажа **стирается** — до его
линии одежды, найденной тем же способом, что и у донора. Вклейка садится прямо в
воротник.

Раньше было наоборот: шея персонажа сохранялась, и донорская садилась на неё.
Это давало две шеи и шов на горле — самое заметное место портрета. Стык по линии
одежды прячут воротник и плечи, и на них же приходится полоса зоны 2.

### Тон кожи: по зонам и по коже персонажа

Две вещи, на которых коррекция спотыкалась, и обе видны только на замере.

**Эталон брался из-под вклейки.** Статистика шаблона считалась по тем же
пикселям, которые накрыты маской донора. Пока вклейка садилась ровно на лицо
персонажа, это работало; с множителем размера и сдвигом шеи под маской донора
оказались воротник и фон, и «тон кожи шаблона» стал считаться по чему угодно,
кроме кожи. Теперь эталон — отдельная маска: лицо и шея **персонажа**, с
обрезанной кромкой (на границе с фоном пиксели наполовину фоновые).

**Одна поправка на всю кожу.** Лицо на фотографии освещено, шея под подбородком
лежит в собственной тени. Единая поправка подгоняет статистику по площади, то
есть по лицу, и шея остаётся с фотографической тенью. Замер на `spread_05`: по
всей коже ΔL ≈ 4, а по одной шее — 45. Поэтому зон две, у каждой свой эталон:

| Зона | ΔL до правки | ΔL после |
| --- | --- | --- |
| лицо | 4.2 | 4.2 |
| шея | 44.9 | **4.3** |

Размеры зон видны в `[geometry]` как `skin: face N px, neck M px`. Ноль в шее
означает, что коррекция до неё не дошла — ровно так выглядела «оторванная по
цвету» шея.

#### Направление коррекции

`ML_COLLAGE_COLOUR_DIRECTION` задаёт, кто под кого подстраивается:

* `to_donor` (по умолчанию) — **тело персонажа под вклейку**. Голова остаётся
  реалистичной, а нарисованные руки и грудь подкрашиваются под её тон. Логика
  простая: на портрете разница в тоне бросается в глаза, на руках — нет.
* `to_template` — прежнее направление, вклейка под персонажа.

**Ограничение, которое надо знать.** Открытая кожа персонажа ищется по хроме
внутри его силуэта, и на наших обложках этот признак не работает надёжно. Замеры
на `spread_05` (отклонение от тона лица персонажа):

| Что | \|Δa\| | \|Δb\| |
| --- | --- | --- |
| собственная рука персонажа | 17 | 1 |
| его шея и грудь | 13 | 9 |
| **бежевый жилет** | **4** | **2** |
| шип динозавра | 8 | 6 |

То есть по цвету ткань и декорация ближе к коже, чем сама кожа. Связность тоже
не спасает: сегментатор отдаёт персонажа и динозавра **одним компонентом на
100%** силуэта. Поэтому коррекция сознательно локальная — `collage_body_reach`
(`1.2` высоты лица от низа вклейки) ограничивает её окрестностью стыка, а если
под неё попадает больше 15% силуэта, в лог уходит `warning`. Ноль отключает
подкраску тела совсем, не трогая остального.

`ML_COLLAGE_COLOUR_MATCH` (`0.8`) подгоняет среднее и разброс по каналам **LAB**. Геометрию это не трогает вовсе (поканальная кривая), но
снимает разницу между светом фотостудии и светом иллюстрации: при strength 0.2
модель не успевает свести освещение сама, и лицо остаётся фотографией на
обложке. LAB, а не BGR, потому что там яркость отделена от цвета и подгонка
тона не задевает светотеневой рисунок лица.

**Волос коррекция не касается.** Их переносят ради того, чтобы они остались
волосами заказчика; подтянуть их к палитре персонажа означало бы перекрасить
донора в нарисованного героя. Смешивание идёт в BGR, а не в LAB, ровно поэтому:
обратный перевод LAB → BGR не побитовый, и пиксели с нулевым весом уехали бы на
единицу-две просто оттого, что их прогнали через цветовое пространство.

### Три зоны маски: разная работа — разная сила

Работы на холсте две, и сила им нужна противоположная. Одна маска с одним
`strength` обслужить обе не может: того, что достаточно для шва, не хватит
восстановить фон, а того, что восстановит фон, хватит стереть лицо. Поэтому зон
три, и **два прохода инпейнтинга** — у эндпоинта одна сила на вызов.

| Зона | Что это | strength | Что от модели нужно |
| --- | --- | --- | --- |
| **1. Черты лица** | контур из сетки | **0…0.4×** | почти ничего: защита ослабляется, но не снимается |
| **2. Стыки** | кольцо по контуру новых волос + полоса на стыке шеи с телом | `0.26` | свести тон и цвет кожи от шеи донора к телу персонажа, положить контактную тень |
| **3. Дыра в фоне** | где была чужая причёска, а новая голова не накрыла | `0.85` | нарисовать фон заново: небо, ветку, крыло птеродактиля |
| **4. Сама вклейка** | голова и шея, отступив от контура внутрь | `0.35` | перевести фотографию в живопись: мазок кисти, зерно холста |
| **5. Весь кадр** | маски нет вовсе | `0.18` | одно зерно холста поверх всего разворота |

Зона 3 появилась после разбора конкретного брака. У героя обложки грива до
плеч, у заказчика ёжик; после вклейки от старой шевелюры остаётся зона в
пол-неба, `_erase_template_head` затирает её вместе с фоном и всем, что в нём
было, а на `strength 0.26` модель кладёт поверх мыла только касание кисти.
Восстановить утраченное можно лишь сгенерировав его заново — отсюда 0.85 и
отдельный вызов.

Зона 4 появилась последней и меняет прежнюю гарантию. Раньше лицо вычиталось из
масок целиком — «модель до него физически не дотягивается», — и сходство было
защищено железно. Но и результат выходил честный: фотографическое лицо на
картине маслом, склейка видна не по шву, а по фактуре. Цветокоррекция тут не
помогает вовсе — тон подогнать можно, мазок кисти нельзя, это структура, а не
цвет. Поэтому защита лица теперь не вычитается, а **ослабляется**:
`paste_guard_strength` (по умолчанию `0.6`) задаёт, какая её доля остаётся.
Единица — прежнее поведение, ноль — лицо открыто наравне с волосами.

Это осознанный размен: на `0.35` фактура появляется, а черты держатся; выше
`0.45` начинает меняться разрез глаз. Две ручки на выбор — `strength` прохода и
доля защиты.

Пятая зона — не зона, а финальный проход **по всему кадру без маски**. Каждый
проход по маске оставляет за собой границу: под маской поверхность одна, вне её
другая. По отдельности эти границы слабые, вместе складываются в «эффект
аппликации», когда видно не шов, а разницу материала. Проход на `0.15–0.20`
кладёт поверх всего единое зерно холста.

Сила здесь критична: маски нет, защиты лица тоже, и выше `safe_strength` (`0.22`)
проход перестаёт быть текстурным и становится перерисовкой разворота — сразу
везде. И он трогает те части обложки, которых пайплайн до сих пор не касался
вовсе: текст и мелкие детали после него уже не побитово те же.

Порядок обязателен: **фон → фактура → стык → общая текстура**. Мазок ложится на
уже восстановленный фон, стык сводится по свежим мазкам, а зерно холста идёт
последним — оно затирает границы предыдущих проходов, и любой проход после него
завёл бы новую. Стык сводит вклейку с
тем, что вокруг, и «вокруг» к этому моменту должно быть уже нарисовано — иначе
второй проход будет старательно сводить края с мылом. Результат первого вызова
уходит во второй ссылкой на CDN, без повторной загрузки 25-30 МБ.

Зона 3 отступает от вклеенной головы на `hole_margin_ratio`: под 0.85 всё, что
она накрывает, исчезает, и подпускать её к контуру новых волос нельзя — полоса
между ними принадлежит зоне 2. Если дыра меньше `min_area_ratio` кадра (у героя
со стрижкой её почти нет), второй вызов не делается вовсе.

**Зоны обязаны перекрываться, но горячая — держаться от волос.** Требования
тянут в разные стороны, и первая попытка их совместить дала брак. Зазор между
зонами оставлял полосу сырой заливки (13% стёртой площади) — грязный контур
вокруг головы; но когда зону 3 подвели к вклейке вплотную, она стала подходить к
причёске на 6–10 px, а на `0.85` с промптом «фон, никаких голов и волос» край
волос просто съедается и по нему остаётся светлая кайма.

Разрешается это тем, что кольцо зоны 2 **несимметрично**: внутрь контура оно
заходит на `edge_ratio` (`0.03` — там волосы заказчика), наружу на
`edge_outer_ratio` (`0.16` — там заливка). Зона 3 при этом держится на
`hole_margin_ratio` (`0.12`) от вклейки, то есть 20–37 px вместо прежних 6–10, а
перекрытие обеспечивает внешняя половина кольца. Связь `hole_margin_ratio <
edge_outer_ratio` проверяется в `RefineProfile.validate`.

**Доли масок меряются от вклеенного лица** (`collage.face_height_paste`), а не от
лица персонажа. При `ML_HEAD_SCALE_MULTIPLIER = 0.7` голова на треть меньше
персонажной, и кольца, посчитанные от неё, оказывались на треть шире нужного —
как раз там, где и виден контур.

Лицо защищено отдельно и явно: контур из сетки растушёвывается и **вычитается**
из обеих масок последним действием. Черты оказываются под нулём — модели
недоступны вовсе. У самой кромки челюсти маска гасится лишь наполовину: иначе
фотографическая щека встречалась бы с живописью встык, без единого пикселя на
переход.

Доли масок — часть профиля второго шага (`MaskProfile` в
`refine/profiles.py`), а не отдельные переменные: ширина градиента и `strength`
подбираются вместе, и разъехаться они не должны. Поэтому и маски, и запрос
`pipeline.py` собирает из одного профиля.

| Поле | Значение | Что задаёт |
| --- | --- | --- |
| `edge_ratio` | `0.03` | насколько кольцо стыка заходит внутрь контура волос |
| `edge_outer_ratio` | `0.05` | насколько оно уходит наружу; до зоны фона дотягивается градиент за ним |
| `neck_ratio` | `0.12` | толщина полосы на стыке шеи с телом |
| `guard_ratio` | `0.06` | растушёвка защиты лица |
| `feather_ratio` | `0.04` | спад 255 → 0 по краям зоны стыков |
| `gradient_ratio` | `0.05` в `blend` и `stylise`, `0` в `seam` | ширина градиента от стыка наружу |
| `hole_margin_ratio` | `0.12` | отступ зоны фона от вклеенной головы |
| `hole_feather_ratio` | `0.05` | спад по краям зоны фона |
| `paste_inset_ratio` | `0.04` | отступ зоны стилизации внутрь от контура |
| `paste_guard_strength` | `0.6` | какая доля защиты лица остаётся в зоне стилизации |

Спад делается не простым размытием, а через `soften` (дилатация на `feather`,
затем размытие тем же ядром): кольцо вдоль волос узкое, и симметричный гауссиан
сбил бы его пик заметно ниже 255 — зона стыка открылась бы модели лишь частично.

Доли — от высоты лица **на шаблоне**, а не в пикселях: обложки приходят и в 4K,
и превью-размером.

### Мимика: интерфейс есть, реализации нет

Обложка — не одна картинка, а разворот за разворотом, и на каждом оказывается
одно и то же выражение лица. `expression.py` задаёт место, где это чинится:
трансформер получает вырезанную голову (кадр, альфу и сетку) **до** переноса в
шаблон. Раньше нельзя — нет вырезанного лица; позже — лицо уже вклеено, и правка
поедет вместе с фоном обложки.

Реализации пока нет намеренно. Любая переделка мимики — это изменение геометрии
лица, то есть ровно то, от чего уходили, вводя жёсткий коллаж. Сначала нужен
инструмент, сохраняющий личность (кандидаты: LivePortrait на fal, локальный варп
по сетке с ограничением смещений), и способ проверить, что заказчик остался
узнаваем.

До тех пор незнакомая эмоция получает честный `501 EXPRESSION_NOT_SUPPORTED`, а
не молча возвращённое неподвижное лицо: молчаливый отказ обнаружился бы уже на
печати тиража. Добавление трансформера — регистрация объекта, больше править
ничего не нужно:

```python
class Smile:
    name = "smile"
    def apply(self, face: expression.Face) -> expression.Face: ...

expression.register(Smile())
```

После регистрации значение сразу становится допустимым в параметре `emotion`
эндпоинта `/face-swap` и появляется в `/health/ready`.

### Модель: почему именно inpaint по маске

`fal-ai/flux-kontext-lora/inpaint` принимает `image_url` (**коллаж**) +
`mask_url` (наша маска) + `reference_image_url` (фото заказчика). Схема вызова
осталась прежней, изменился её смысл: под маску уходит уже собранная
аппликация, а референс лишь подсказывает модели, чью голову она обводит.
Идентификатор эндпоинта с тех пор переехал в профиль — `stylise_controlnet`
работает через другой, принимающий карты.

Что пробовали и отвергли:

| Модель | Почему не подошла |
| --- | --- |
| `easel-ai/advanced-face-swap` | ищет лицо собственным детектором, а тот обучен на фотографиях и **на нарисованных обложках лица не находит вовсе**. Настройками не лечится |
| `fal-ai/flux-pulid` | только `prompt` + `reference_image_url`. Ни маски, ни базового изображения — генерирует картинку с нуля |
| `fal-ai/ip-adapter-face-id` | только `prompt` + `face_image_url`, маски нет. То же самое |
| `fal-ai/flux-general/inpainting` + `ip_adapters` | XLabs flux-ip-adapter переносит **стиль, а не личность**: два прогона с одним донором дали два чужих несвязанных лица |

Вывод, который стоит помнить: связки «identity-модель + инпейнтинг по маске» на
fal нет, а специализированные лицевые модели спотыкаются о рисунок раньше, чем
дело доходит до качества переноса.

### Второй шаг: профиль, стратегия, карты

Гиперпараметры второго шага не разложены по конфигу поштучно — они живут
**набором**. Strength, ширина градиента маски, веса ControlNet и промпт
подбираются вместе, и по отдельности не значат ничего: маска-плато уместна на
0.20 и даёт ступеньку на 0.50, а Canny с весом 0.65 нужен ровно затем, чтобы
удержать черты на этой силе. Набор называется профилем и лежит в
`app/pipelines/refine/profiles.py` — замороженный dataclass, ничего не
вызывающий и ни от чего не зависящий.

| Профиль | strength | Маска | ControlNet | Когда |
| --- | --- | --- | --- | --- |
| `seam` | 0.20 | плато + растушёвка | нет | консервативный режим: модель только сводит шов |
| `blend` (по умолчанию) | 0.26 + 0.85 по фону | градиент 0.05 | нет | рабочий: стык сводится мягко, дыра от чужой причёски рисуется заново |
| `stylise` | 0.50 | градиент 0.12 | нет | стилизация с перерисовкой. **Без карт рискует контуром причёски** |
| `stylise_controlnet` | 0.50 | градиент 0.12 | Canny + Depth | то же, но геометрию держат карты, а тени ставит объём |

Почему по умолчанию именно `blend`. Рабочий эндпоинт — `kontext-inpaint` с нашей
LoRA, и стиль обложек держится на ней; уходить с него ради ControlNet значит
потерять этот стиль. Поэтому дефолт собран из того, что работает на нём:
**градиентная маска** сводит шею и контур волос мягко, а **strength 0.26**
оставляет геометрию причёски в покое — выше ~0.28 она плывёт, и без карт
удержать её нечем. Тени на такой силе даёт промпт и LAB-коррекция кожи из
`collage.py` (`ML_COLLAGE_COLOUR_MATCH`, по умолчанию 0.8), а не карта глубины.
`0.28` стоит и в `safe_strength`: внутри диапазона лог молчит, выше — `warning`.

Выбор — `ML_REFINE_PROFILE`. Точечная правка — `ML_REFINE_STRENGTH`,
`ML_REFINE_GRADIENT_RATIO`, `ML_REFINE_CONTROLS` и остальные `ML_REFINE_*`:
пустое значение означает «взять из профиля». Свой набор регистрируется без
правки файла:

```python
profiles.register(replace(profiles.get("blend"), name="soft", strength=0.22))
```

Профиль проверяется до сети (`RefineProfile.validate`). Несобираемая связка —
например, карты ControlNet при эндпоинте, который их не принимает, — стоит
`500` с внятным текстом и `degraded` в `/health/ready`, а не отказа fal после
трёх загрузок в CDN.

#### Градиентная маска

На `strength 0.20` форма маски внутри почти не имела значения: модель едва
касалась пикселей, и разница между «обрабатывается на 100%» и «на 60%» была
неразличима. Уже на 0.26 она начинает работать заметно, а на 0.50
перерисовывает открытое по-настоящему — и плато означает, что вся область под
ним переписана одинаково сильно, а по его границе идёт ступенька ровно той
высоты, на которую подняли strength.

Поэтому маска стала конусом: 255 точно на стыке, линейный спад на
`gradient_ratio` высоты лица в обе стороны. Спад строится
`distanceTransform`, а не гауссианом — гауссиан размывает и сам стык, теряя на
нём полные 255. На реальном развороте (`spread_03`, лицо 314 px) доля полутонов
в зоне растёт с 28.6% до 44.1% при почти неизменной площади: то же место, но
без ступеньки. Защита лица вычитается последней и при градиенте тоже — черты
получают ровный ноль.

#### Карты управления

`stylise_controlnet` добавляет два канала входа, которые модель обязана
соблюдать независимо от того, сколько шума насыпали сверху:

| Карта | Чем считается | Вес | Окно | Роль |
| --- | --- | --- | --- | --- |
| `canny` | локально, `cv2.Canny`, пороги 100/200 | 0.65 | 0–80% шагов | держит рисунок: контур причёски, линию челюсти, разрез глаз. Главный предохранитель личности на высоком strength |
| `depth` | эндпоинтом, из самого коллажа | 0.45 | 0–50% шагов | **тени**: по объёму видно, что голова выступает над плечами, и контактная тень ложится под подбородок, а не куда придётся по промпту |

Глубина считается на стороне fal намеренно: локальный инференс глубины (MiDaS)
потянул бы torch, а от локальных весов в этом сервисе уходили осознанно. Отсюда
поле `source` у `ControlSpec` — `canny` строится здесь, `image` уезжает кадром.

**Эндпоинт для карт нужен другой.** `kontext-inpaint` их не принимает, а лишний
ключ он не игнорирует, а заворачивает весь запрос — эта связка ловится в
`validate()` до сети. У `stylise_controlnet` подставлен
`fal-ai/flux-general/inpainting`: это тот же эндпоинт, через который пробовали
`ip_adapters`, то есть модульные ключи он берёт. **Точную форму списка карт —
имя ключа и имена полей внутри — надо подтвердить первым же боевым прогоном**:
схему у fal мы уже один раз узнавали постфактум. Имя ключа вынесено в
`control_field`, форма записи — в `inpaint_controlnet.py`.

#### Переключение подхода целиком

Профиль меняет числа. Когда меняется сам способ получить личность, нужен другой
код — для этого в профиле есть поле `strategy`, а в `refine/base.py` реестр:

| Стратегия | Откуда берётся личность | Состояние |
| --- | --- | --- |
| `inpaint_controlnet` | готовыми пикселями в коллаже | работает |
| `identity_embedding` | матрицей эмбеддингов (Nx512, InsightFace) | контракт есть, реализации нет — `501` |

Второй подход заложен, но не сделан, и это не забывчивость: связки
«identity-модель + инпейнтинг по маске» на fal нет (см. таблицу выше — и
`flux-pulid`, и `ip-adapter-face-id` работают без базового кадра), а считать
сами эмбеддинги нечем — InsightFace тянет onnxruntime и свои веса. Что именно
нужно доделать, когда эндпоинт появится, перечислено в
`refine/identity_embedding.py`. До тех пор стратегия отвечает честным `501`, а
не молча отрабатывает инпейнтингом: молчаливая подмена обнаружилась бы уже на
печати тиража.

Своя стратегия добавляется регистрацией объекта — ни `pipeline.py`, ни
`fal_api.py` править не нужно:

```python
class MyRefiner:
    name = "my_refiner"
    def refine(self, request: refine.RefineRequest, profile) -> refine.RefineResult: ...

refine.register(MyRefiner())
```

`fal_api.py` после этого разделения знает только транспорт: положить файл в
CDN, дождаться инференса, забрать результат. Схему запроса собирает стратегия,
и зафиксирована она тестами (`tests/test_refine.py`) — на ней уже обжигались
вживую, а выяснялось это только после боевого прогона.

### Известные ограничения

- **Мелкое лицо на обложке.** mediapipe Face Mesh не находит лицо мельче ~20%
  ширины кадра. Лицо нужно найти в обоих кадрах, обходного пути нет — обложка в
  полный рост завернётся как `422 NO_FACE_DETECTED` (в `details.image` видно,
  какой именно кадр не подошёл).
- **Ракурс.** Перенос плоский: если на фотографии лицо в три четверти, а на
  обложке анфас, никакое двумерное преобразование их не совместит. Лечится
  только другим исходником.
- **Разрешение фотографии.** Лицо на фото должно быть не мельче, чем на
  обложке: `scale > 1` означает растягивание, и вклейка выйдет мыльной. Уходит
  в лог `warning`.
- **Причёска персонажа сильно больше донорской.** Стирание оставляет за головой
  ровное пятно фона без текстуры живописи, и на `strength 0.2` модель кладёт
  поверх только мазок, а не восстанавливает мазки холста. Ореола там больше нет,
  но и деталей фона тоже. Признак — `erased_ratio` выше 0.5.
- **Длинные волосы.** Область головы — эллипс с фиксированными пропорциями, а
  ниже челюсти остаётся только узкая колонна шеи: коса до пояса перенесётся
  обрезанной у подбородка. Это цена чистого среза — иначе вместе с волосами
  приезжает одежда.
- **Мимика не меняется.** Точка расширения есть, трансформеров нет: любая
  эмоция, кроме `neutral`, отвечает `501`.
- **Лицевые эмбеддинги не пробрасываются.** Контракт стратегии заложен, но
  считать их нечем и передавать некуда: `identity_embedding` отвечает `501`.
- **ControlNet не проверен вживую.** Карты собираются и уезжают, но форму
  списка у `fal-ai/flux-general/inpainting` подтвердит только первый боевой
  прогон — схему у fal мы уже один раз узнавали постфактум. Профиль
  `stylise_controlnet` поэтому не выбран по умолчанию — и, пока стиль держится
  на нашей LoRA, уход с `kontext-inpaint` ради карт не окупается.
- **Тени только промптом.** Карта глубины поставила бы контактную тень по
  объёму, но она требует ControlNet и ухода с эндпоинта, где висит наша LoRA.
  В `blend` тень просит промпт, а разницу освещения снимает LAB-коррекция кожи
  на первом шаге. При сомнениях откат — `ML_REFINE_PROFILE=seam`, без правки кода.
- **Четыре вызова fal на заказ.** Зонам нужна разная сила, а у эндпоинта она одна
  на вызов: фон 0.85, фактура 0.35, стык 0.26, общая текстура 0.18. Стоимость и
  время растут вчетверо против одного прохода. Проходы отключаются по
  отдельности: `stylise=None` оставляет вклейку фотографической,
  `background=None` — фон на локальной заливке, `unify=None` — каждая зона со
  своей поверхностью.
- **Фактура против сходства.** Зона 4 открывает лицо модели — не полностью, но
  открывает. На `0.35` черты держатся, выше `0.45` начинает меняться разрез
  глаз. Если сходство важнее фактуры, поднимайте `paste_guard_strength` к
  единице или отключайте проход.
- **Шея берётся такой, какая есть на фото.** Свитер под горло — шеи почти не
  будет, и голова снова окажется без опоры; кадр, обрезанный под подбородком, —
  то же самое. Видно по `collage.neck_ratio` в `X-Swap-Meta`.
- **Одно лицо за запрос.** Берётся крупнейшее найденное; `faces_detected` и
  `faces_swapped` в метаданных всегда `1`.
- **Время.** Два прогона сегментатора и заливка фона добавляют ~13–18 с на
  4K-обложке поверх времени инференса (с `ML_COLLAGE_ERASE_METHOD=telea` или
  `ns` — на 20–25 с больше). Вызов и раньше шёл только из фоновой задачи.

## Эндпоинты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | liveness — процесс жив, ничего не проверяется |
| `GET` | `/health/ready` | readiness — зависимости и `FAL_KEY`, `503` если не готов |
| `POST` | `/face-swap/analyse` | детекция лица (multipart `image`) |
| `POST` | `/face-swap` | замена лица, возвращает изображение + заголовок `X-Swap-Meta` |

```bash
curl http://localhost:8000/health

curl -X POST http://localhost:8000/face-swap \
  -F source=@photo.jpg -F target=@cover.png \
  -o result.png -D -
```

`/face-swap/analyse` отдаёт габариты найденного лица — Node.js API использует его
для предпросмотра, чтобы не гонять платный инференс:

```json
{ "faces": [{ "bbox": { "x": 351, "y": 184, "width": 297, "height": 316 },
              "landmarks": 478 }], "count": 1 }
```

### Параметры `/face-swap`

Работают: `source`, `target`, `emotion`, `output_format` (`png` | `jpg`/`jpeg`).

`emotion` — мимика вклеиваемого лица. Пусто или `neutral` — лицо как снято;
любое другое значение сейчас отвечает `501` (см. «Мимика»). Node пробрасывает
поле как есть, через `options` в `faceSwap()`, — менять клиент не потребуется,
когда появятся трансформеры.

Форма принимает также `target_face_index`, `swap_all_faces`, `enhance`,
`style_strength` и `art_style`, но **пайплайн их игнорирует**: это остатки
контракта локального пайплайна с постобработкой на OpenCV. Оставлены, чтобы не
ломать вызовы Node.js API; ни одно из них сейчас ни на что не влияет.

### Метаданные результата

Изображение возвращается бинарно, метаданные — в заголовке `X-Swap-Meta` (JSON),
чтобы Node мог сразу сохранить файл без base64-обвязки:

```json
{"faces_detected": 1, "faces_swapped": 1,
 "model": "fal-ai/flux-kontext-lora/inpaint",
 "strength": 0.2, "guidance_scale": 2.5, "steps": 50,
 "output_format": "png", "seed": 1394872001,
 "collage": {"scale": 0.986, "rotation_deg": 0.63, "emotion": "neutral",
             "colour_match": 0.8, "segmenter": "u2net_human_seg",
             "head_fill": 0.659, "head_px": 193898,
             "face_height_target": 274.0,
             "erased_ratio": 0.074, "template_head_px": 202168}}
```

Блок `collage` — отчёт первого шага, и при жалобе «не похож» смотреть надо
сюда:

| Поле | О чём говорит |
| --- | --- |
| `scale`, `rotation_deg` | во сколько раз уменьшена и на сколько повёрнута голова. `scale > 1` — вклейка растянута и будет мыльной |
| `head_fill` | доля эллипса, занятая силуэтом. Около нуля — сегментатор промахнулся; около единицы — причёска упёрлась в границу области и могла обрезаться |
| `erased_ratio` | сколько головы персонажа пришлось стереть. Выше 0.5 — фон за ней домысливается. `null` — сегментатор не нашёл голову на обложке, шаг пропущен |
| `emotion` | какой трансформер мимики применялся |

### Ошибки

Все — единым JSON `{"error": {"code", "message", "details"}}` из
`app/core/errors.py`:

| Код | HTTP | Когда |
| --- | --- | --- |
| `INVALID_IMAGE` | 400 | файл не читается, неподдерживаемый формат, битые параметры маски или коллажа |
| `PAYLOAD_TOO_LARGE` | 413 | файл больше `ML_MAX_UPLOAD_MB` |
| `NO_FACE_DETECTED` | 422 | mediapipe не нашёл лица — на обложке или на фотографии, в `details.image` видно, где именно |
| `MASK_MISSING` | 500 | маска не построена — дефект вызывающего кода, до сети запрос не доходит |
| `EXPRESSION_NOT_SUPPORTED` | 501 | запрошена эмоция, для которой нет трансформера. Не 400: запрос корректен, возможности пока нет |
| `FAL_REQUEST_FAILED` | 502 | отказ fal: авторизация, баланс, сеть, ошибка модели, пустой ответ |
| `FAL_NOT_CONFIGURED` | 503 | не задан `FAL_KEY` |
| `SEGMENTER_UNAVAILABLE` | 503 | rembg не установлен, не смог скачать веса или не нашёл голову на фотографии |

Загрузка изображений в CDN fal обёрнута намеренно: она идёт до инференса и падает
первой, а необёрнутое httpx-исключение дошло бы до FastAPI как `500 text/plain` и
сломало бы JSON-контракт с Node.


```
[geometry] scale=1.401 mark=umeyama marks={'cheeks': 1.417, 'eyes': 1.582, 'face_height': 1.336,
'jaw': 1.413, 'pupils': 1.528} | anchor=22.3 px (collar) | neck=0.241 (frame) |

```

Числа в самом тексте сообщения намеренно: `X-Swap-Meta` виден только тому, кто
читает HTTP-ответ ml-сервиса напрямую, а до браузера он не доходит — Node-очередь
отдаёт фронту статусы, а не заголовки. Остальная диагностика идёт через
`extra={...}` и печатается рядом с сообщением в обоих форматах консоли.

JSON-логи пишутся в `logs/`:

| Файл | Содержимое |
| --- | --- |
| `logs/app.log` | активный файл: все записи, включая логи uvicorn |
| `logs/error.log` | активный файл: только `error` и выше |
| `logs/app.2026-07-23.1.log` | ротированные файлы |

### Ротация

`app/core/rotation.py` — `TimedRotatingFileHandler`, расширенный проверкой
размера, чтобы политика совпадала с Node (`pino-roll`):

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `ML_LOG_ROTATE_WHEN` | `midnight` | когда ротировать (`midnight`, `H`, `D`, `S`) |
| `ML_LOG_FILE_MAX_MB` | `20` | досрочная ротация по объёму |
| `ML_LOG_BACKUP_COUNT` | `14` | сколько ротированных файлов хранить |

Файл роняется по наступлению суток либо раньше при превышении объёма; имя
ротированного файла — `app.<дата>.<номер>.log`, как у Node. Индекс нужен для
нескольких ротаций по размеру за одни сутки.

Два отличия от Node — следствие устройства stdlib:

- активным всегда остаётся `app.log`, дата появляется только у ротированных
  файлов (у `pino-roll` датирован и активный файл);
- удаление старых файлов реализовано в `_prune()`: штатное опирается на схему
  имён stdlib и не находит файлы, переименованные `namer`. Сортировка идёт по
  дате и индексу из имени, а не по `mtime` — на Windows у файлов одной серии
  ротаций метки времени совпадают.

В консоль по умолчанию идёт читаемый формат; `ML_LOG_JSON=true` включает JSON и
там. Поля совпадают с Node-сервисом (`time`, `level`, `service`, `scope`,
`message`, `request_id`), поэтому логи двух сервисов грепаются одинаково:

```json
{"time": "2026-07-23T03:49:04.369Z", "level": "info", "service": "ml-service",
 "scope": "http", "message": "GET /health/ready → 503",
 "request_id": "trace-e2e-1784778544", "status_code": 503, "duration_ms": 3.84}
```

`RequestIdMiddleware` принимает `X-Request-ID` от Node.js API (или генерирует
UUID), кладёт его в `contextvar`, возвращает в заголовке ответа и пишет
access-лог со статусом и длительностью. Штатный access-лог uvicorn приглушён до
`WARNING`, чтобы не дублировать записи без `request_id`.

Произвольные поля добавляются через `extra`:

```python
log.info("маска лица построена", extra={"face_height": 316, "feather_px": 32})
```

```
    expression.py             мимика: интерфейс трансформера и реестр
    collage.py                шаг 1: перенос головы подобием и жёсткая вклейка

      profiles.py             шаг 2: ВСЕ гиперпараметры — strength, пороги, веса, эндпоинты
      base.py                 контракт стратегии и реестр: как переключается подход
      controls.py             карты ControlNet: Canny локально, depth кадром
      inpaint_controlnet.py   стратегия «инпейнтинг по маске + ControlNet»
      identity_embedding.py   стратегия «проброс эмбеддингов»: контракт, 501

  collage_preview.py          первый шаг локально, по стадиям, без вызова fal
tests/                        pytest, работают без сети, без FAL_KEY и без весов rembg
```

Разделение ролей: `segmentation.py` знает про силуэт и ничего про обложку;
`collage.py` отвечает за внешность и не знает про fal; `pipeline.py` решает, что
и по какой маске обрабатывается; `refine/` знает, чем и с какими числами
выполняется второй шаг; `fal_api.py` знает только про транспорт до fal и
ничего — про смысл операции. Числа второго шага при этом отделены от кода:
`profiles.py` не делает ни одного вызова, а стратегии не содержат ни одной
константы. `expression.py` не зависит ни от чего из этого:
он получает вырезанную голову и возвращает её же.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Ни сети, ни весов: клиент fal подменяется фейком, детектор лиц — общей
заглушкой из 468 точек (`tests/conftest.py`), сегментатор — синтетическим
силуэтом. Проверяются главные гарантии пайплайна — преобразование не может
исказить пропорции донора, вклеенные пиксели совпадают с фотографией, волосы не
перекрашиваются коррекцией тона, а лицо получает в маске ровный ноль, — плюс
область головы и срез шеи, стирание причёски персонажа, реестр мимики, профили
второго шага и их проверку до сети, переключение стратегии по имени, схему
аргументов эндпоинта вместе с картами ControlNet, обработку ошибок транспорта,
ротацию логов и проброс `X-Request-ID`.

Линтер — `ruff check app tests` (конфигурация в `pyproject.toml`).

### Предпросмотр аппликации без fal

Настраивается сейчас первый шаг, а второй платный и небыстрый. `collage_preview.py`

## Интеграция с Node.js API

Node-сервис ходит на `http://localhost:8000` (`ML_SERVICE_URL`). Готовность этого
сервиса — готовность всего продукта: замена лица и есть его единственная работа,
поэтому Node отдаёт `503` на `/health/ready`, когда ML недоступен.

```js
const res = await fetch('http://localhost:8000/health/ready');
const ready = res.ok; // 503 → заказы принимать бессмысленно
```

Вызов долгий (облачный инференс — десятки секунд), поэтому Node дёргает
`/face-swap` только из фоновой задачи-воркера, а не из HTTP-обработчика.
