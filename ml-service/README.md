# ml-service — ML-микросервис (Python 3.11 + FastAPI)

Замена лица на обложке: заказчик присылает своё фото, сервис возвращает обложку
с его лицом. Вызывается из Node.js API по HTTP.

Локальных весов нет. Локально считаются **маска лица и коллаж** — mediapipe
везёт свою модель внутри пакета, остальное делает OpenCV, — а инференс идёт на
**fal.ai**. Отсюда и лёгкость установки: ни компилятора C++, ни CUDA, ни
гигабайтов чекпойнтов.

Пайплайн двухшаговый: сходство переносится локально жёсткой вклейкой пикселей
фотографии, а модель лишь стилизует готовый коллаж на очень низком `strength`.
Подробности и причины — в разделе «Как устроена замена лица».

> Сервис предназначен для работы с фотографиями, на использование которых
> получено согласие (заказчик книги и её получатель).

## Установка

```powershell
cd ml-service
.\scripts\setup_venv.ps1              # обычная установка
.\scripts\setup_venv.ps1 -Recreate    # пересоздать окружение
.\scripts\setup_venv.ps1 -NoDev       # без pytest/httpx/ruff
```

Linux/macOS:

```bash
./scripts/setup_venv.sh [--recreate] [--no-dev]
```

Скрипт: находит Python 3.11 → создаёт `.venv` → ставит `requirements.txt` +
dev-зависимости → копирует `.env.example` в `.env` → проверяет импорты.

Python строго 3.11 (`>=3.11,<3.12` в `pyproject.toml`) — ограничение mediapipe.

> `setup_venv.ps1` сохранён в UTF-8 **с BOM**: Windows PowerShell 5.1 читает `.ps1`
> без BOM как ANSI и ломается на кириллице в строках. При правке файла редактором
> сохраняйте кодировку.

### FAL_KEY

Ключ читается `fal-client` напрямую из окружения как `FAL_KEY` — **без префикса
`ML_`**, в отличие от остальных настроек. Без него `/health` по-прежнему `ok`
(процесс жив), а `/health/ready` отдаёт `503 degraded`:

```json
{
  "status": "degraded",
  "runtime": { "mediapipe": true, "opencv": true, "fal_client": true },
  "provider": {
    "model": "fal-ai/flux-kontext-lora/inpaint",
    "key_present": false,
    "key_env": "FAL_KEY"
  },
  "mask": {
    "detector": "mediapipe/face_mesh",
    "padding_ratio": 0.06,
    "feather_ratio": 0.1
  },
  "reason": "не задан FAL_KEY"
}
```

`runtime` и `provider` разделены намеренно: сразу видно, чего не хватает —
пакета или ключа.

## Как устроена замена лица

Два шага, и разделение между ними принципиальное: **сходство переносится
локально, стилизацию делает модель**.

1. **Коллаж** (`collage.py`, локально, OpenCV + mediapipe) — лицо с фотографии
   переносится в шаблон преобразованием подобия и вклеивается оригинальными
   пикселями. Геометрия переносится один в один.
2. **Стилизация** (`fal_api.py`, на fal.ai) — тот же коллаж уходит в
   `fal-ai/flux-kontext-lora/inpaint` по маске из `mask_generator.py`, но с
   **очень низким strength (0.22)**: модель накладывает мазок кисти, согласует
   свет и растворяет шов, а на изменение черт лица шума просто не хватает.

Оркестрация — `face_swap/pipeline.py`, единственный вход для API-слоя.

### Почему не один шаг

Прежняя схема была одношаговой: fal получал чистую обложку, маску и фото
заказчика как `reference_image_url` и рисовал лицо сам при `strength 0.82`. При
таком зашумлении область под маской генерируется практически с нуля, и
похожесть держится лишь на том, насколько модель прочитала личность с одного
фото. Портретного сходства это не даёт — черты уезжают, и понизить strength без
коллажа нельзя: под маской лежит лицо чужого персонажа, и на 0.2 оно бы просто
осталось на месте.

Коллаж снимает противоречие. Под маской теперь уже нужное лицо, поэтому низкий
strength не сохраняет чужие черты, а защищает свои:

| | одношаговая схема | коллаж + стилизация |
| --- | --- | --- |
| Кто переносит личность | модель по референсу | `warpAffine` по сетке mediapipe |
| `strength` | 0.82 | 0.22 |
| Что делает модель | рисует лицо заново | кладёт мазок, свет, сводит шов |
| Геометрия лица | как получится | пиксель в пиксель с фотографии |

### Перенос: преобразование подобия, а не аффин

По 18 опорным точкам сетки (углы глаз, спинка и крылья носа, углы рта,
подбородок, скулы, края бровей) методом наименьших квадратов считается
преобразование **подобия**: поворот, единый масштаб, сдвиг. Решение
классическое — Умеяма через SVD ковариации, `collage.similarity_transform`.

Четыре степени свободы вместо шести у полного аффина — это не экономия, а
запрет: аффин подогнал бы донора под форму чужого лица, растянув его по одной
оси, и узнаваемость исчезла бы именно на этом шаге. Матрица вида `[s·R | t]`
такого выразить не может — только повернуть лицо и поменять его размер целиком.

`cv2.estimateAffinePartial2D` считает то же самое, но через RANSAC со
случайными выборками: результат меняется от запуска к запуску, а одинаковые
входы обязаны давать одинаковый коллаж.

Уменьшение (лицо на фото почти всегда крупнее, чем на обложке) идёт в два
приёма: сначала `INTER_AREA` до нужного размера, потом поворот и сдвиг. Одним
`warpAffine` уменьшать нельзя — интерполяция выбрасывает пиксели и контуры
рвутся.

### Что вклеивается и что не вклеивается

Контур вклейки — тот же, что у маски: дуга челюсти снизу, линия бровей сверху
вместо лба. **`rembg` не используется намеренно**: вырезать фон нечего, в контур
лица не попадают ни волосы, ни одежда, ни задник фотографии, — а отдельная
onnx-модель ради этого тянула бы за собой `onnxruntime` и загрузку весов.

Две поправки к жёсткому коллажу, обе в долях высоты лица:

| Параметр | Значение | Зачем |
| --- | --- | --- |
| `ML_COLLAGE_GROW_RATIO` | `0.02` | запас контура за пределы лица: формы лиц разные, и без запаса у края остаётся, например, бровь исходного персонажа — при strength 0.2 модель её уже не уберёт. Выше 0.03–0.04 затягивает волосы и фон с фотографии |
| `ML_COLLAGE_FEATHER_RATIO` | `0.01` | ровно столько, чтобы убрать ступеньку антиалиасинга по контуру. Сведение шва — работа второго шага, а не размытия |

Отдельно — приведение цвета (`ML_COLLAGE_COLOUR_MATCH`, `0.8`): среднее и
разброс по каналам **LAB** подгоняются под лицо шаблона. Геометрию это не
трогает вовсе (поканальная кривая), но снимает разницу между светом фотостудии
и светом иллюстрации. Без него при strength 0.2 модель не успевает свести
освещение, и лицо остаётся фотографией на обложке. LAB, а не BGR, потому что
там яркость отделена от цвета и подгонка тона кожи не задевает светотеневой
рисунок лица.

В `X-Swap-Meta` уезжает отчёт первого шага — `scale`, `rotation_deg`,
`coverage`. Это первое, на что стоит смотреть, если результат вышел непохожим:
`coverage` ниже 0.9 означает, что вклейка не накрыла лицо шаблона целиком
(обычно — разные ракурсы), и в лог уходит `warning`.

### Маска: контур лица, а не прямоугольник

Полигон строится по сетке mediapipe Face Mesh (478 точек) и обводит **только
лицо**: дуга челюсти снизу, линия бровей сверху вместо лба. Прямоугольник от
Face Detection здесь не годится — в него неизбежно попадают волосы и фон, а
перерисованные волосы дают ореолы и рассогласование с иллюстрацией.

Брови приподнимаются на 6% высоты лица (`_BROW_LIFT`): точки сетки лежат по
нижнему краю брови, без подъёма бровь остаётся снаружи маски.

### Профиль краёв: почему padding + feather, а не просто размытие

Первая версия заливала полигон и размывала его по Гауссу ядром 101. Градиент при
этом получается **симметричным относительно контура**: половина растушёвки
съедает само лицо (пиксели по линии челюсти защищены от перерисовки наполовину),
наружу выходит вторая половина. Модели остаётся полоска в пару десятков
пикселей, чтобы свести новое лицо с иллюстрацией, — и она вклеивает его встык.
Результат читается как пластиковая маска поверх обложки.

Сейчас маска строится в три шага:

1. заливка полигона — контур лица;
2. дилатация на `padding + feather` — вокруг лица появляется поле, где модели
   разрешено вести переход;
3. размытие по Гауссу ядром **ровно в ширину `feather`**.

Ядро обрывается точно на границе кольца дилатации, поэтому свёртка на границе
«лицо + padding» видит только белое, а за кольцом — только чёрное. Лицо вместе с
полем остаётся полностью непрозрачным, спад 255 → 0 лежит целиком снаружи.

Замер на круглом лице радиусом 150px в кадре 1000×1000 (высота лица 316px →
padding 19px, feather 32px):

| Расстояние от контура | Значение маски |
| --- | --- |
| −10px (внутри лица) | 255 |
| +20px | 255 |
| +30px | 251 |
| +50px | 142 |
| +70px | 8 |
| +80px | 0 |

Размеры задаются **долями высоты лица**, а не пикселями (`ML_MASK_PADDING_RATIO`,
`ML_MASK_FEATHER_RATIO`): обложки приходят и в 4K, и превью-размером, одно и то
же фиксированное ядро работает на них совершенно по-разному.

Маска строится по **объединению двух контуров** — лица шаблона и вклеенного
коллажа (`mask_from_polygons`). Иначе шов склейки мог бы оказаться снаружи зоны
инпейнтинга, и сглаживать его было бы некому. Контуры заливаются по одному:
`cv2.fillPoly` со списком считает их частями одной фигуры по правилу чёт-нечет
и оставил бы в пересечении дыру — ровно там, где оба лица совпадают.

### Модель: почему именно kontext-inpaint

`fal-ai/flux-kontext-lora/inpaint` принимает `image_url` (**коллаж**) +
`mask_url` (наша маска) + `reference_image_url` (фото заказчика). Схема вызова
осталась прежней, изменился её смысл: под маску уходит уже собранный коллаж, а
референс при strength 0.22 почти ни на что не влияет — он лишь подсказывает
модели, чьё лицо она обводит мазком.

Что пробовали и отвергли:

| Модель | Почему не подошла |
| --- | --- |
| `easel-ai/advanced-face-swap` | ищет лицо собственным детектором, а тот обучен на фотографиях и **на нарисованных обложках лица не находит вовсе**. Настройками не лечится |
| `fal-ai/flux-pulid` | только `prompt` + `reference_image_url`. Ни маски, ни базового изображения — генерирует картинку с нуля |
| `fal-ai/ip-adapter-face-id` | только `prompt` + `face_image_url`, маски нет. То же самое |
| `fal-ai/flux-general/inpainting` + `ip_adapters` | XLabs flux-ip-adapter переносит **стиль, а не личность**: два прогона с одним донором дали два чужих несвязанных лица |

Вывод, который стоит помнить: связки «identity-модель + инпейнтинг по маске» на
fal нет, а специализированные лицевые модели спотыкаются о рисунок раньше, чем
дело доходит до качества переноса.

### Параметры инпейнтинга

Промпт больше не просит нарисовать лицо — оно уже вклеено. Он **запрещает
трогать геометрию** («the same features, the same proportions, the same position
and size») и описывает ровно тот верхний слой, который нужен: медиум обложки,
направление и температура света, растворённый шов. Отрицания идут прямо в
текст: `negative_prompt` эндпоинт не принимает, деть их больше некуда.

| Параметр | Значение | Было | Зачем менялось |
| --- | --- | --- | --- |
| `ML_FAL_STRENGTH` | `0.22` | `0.82` | главная ручка пайплайна. Под маской лежат оригинальные пиксели фотографии, и задача одна — не дать модели до них добраться. Рабочий диапазон **0.15–0.30**: хватает на мазок, свет и сведение шва, но не на изменение черт. Выше ~0.35 (`_SAFE_STRENGTH`) геометрия плывёт и в лог уходит `warning`; ниже 0.15 мазок не набирается и шов остаётся виден |
| `ML_FAL_GUIDANCE_SCALE` | `2.5` | `3.5` | 3.5 нужны были, чтобы перебороть фотофактуру референса. Теперь фотография — основа кадра, а не соперник; на низком strength 2.5 (дефолт эндпоинта) даёт более чистый результат, выше лезут артефакты контраста на считанных шагах денойза |
| `ML_FAL_STEPS` | `50` | `40` | реально исполняется лишь доля `strength` от шагов: 50 × 0.22 ≈ **11 шагов денойза**. При 40 их остаётся 9, и переход в кольце растушёвки набраться не успевает |

**`ip_adapter_scale` у эндпоинта нет.** Лишний ключ он не игнорирует, а
заворачивает весь запрос, поэтому схема аргументов зафиксирована тестами
(`tests/test_fal_api.py`) — на ней уже обжигались вживую, и выяснялось это
только после боевого прогона. Там же зафиксирован и диапазон strength: уехавший
вверх дефолт означал бы молчаливый возврат к одношаговой схеме.

Финальные значения всё равно подбираются глазами по конкретной обложке; все три
переопределяются из окружения без пересборки.

### Известные ограничения

- **Мелкое лицо на обложке.** mediapipe Face Mesh не находит лицо мельче ~20%
  ширины кадра. Лицо нужно найти в обоих кадрах, обходного пути нет — обложка в
  полный рост завернётся как `422 NO_FACE_DETECTED` (в `details.image` видно,
  какой именно кадр не подошёл).
- **Ракурс.** Перенос плоский: если на фотографии лицо в три четверти, а на
  обложке анфас, никакое двумерное преобразование их не совместит. Признак —
  `coverage` в метаданных ниже 0.9 и `warning` в логе; лечится только другим
  исходником.
- **Разрешение фотографии.** Лицо на фото должно быть не мельче, чем на
  обложке: `scale > 1` означает растягивание, и вклейка выйдет мыльной. Тоже
  уходит в лог `warning`.
- **Одно лицо за запрос.** Берётся крупнейшее найденное; `faces_detected` и
  `faces_swapped` в метаданных всегда `1`.

## Эндпоинты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | liveness — процесс жив, ничего не проверяется |
| `GET` | `/health/ready` | readiness — зависимости и `FAL_KEY`, `503` если не готов |
| `POST` | `/face-swap/analyse` | детекция лица (multipart `image`) |
| `POST` | `/face-swap` | замена лица, возвращает изображение + заголовок `X-Swap-Meta` |

```bash
curl http://localhost:8000/health

curl -X POST http://localhost:8000/face-swap \
  -F source=@photo.jpg -F target=@cover.png \
  -o result.png -D -
```

`/face-swap/analyse` отдаёт габариты найденного лица — Node.js API использует его
для предпросмотра, чтобы не гонять платный инференс:

```json
{ "faces": [{ "bbox": { "x": 351, "y": 184, "width": 297, "height": 316 },
              "landmarks": 478 }], "count": 1 }
```

### Параметры `/face-swap`

Работают: `source`, `target`, `output_format` (`png` | `jpg`/`jpeg`).

Форма принимает также `target_face_index`, `swap_all_faces`, `enhance`,
`style_strength` и `art_style`, но **пайплайн их игнорирует**: это остатки
контракта локального пайплайна с постобработкой на OpenCV. Оставлены, чтобы не
ломать вызовы Node.js API; ни одно из них сейчас ни на что не влияет.

### Метаданные результата

Изображение возвращается бинарно, метаданные — в заголовке `X-Swap-Meta` (JSON),
чтобы Node мог сразу сохранить файл без base64-обвязки:

```json
{"faces_detected": 1, "faces_swapped": 1,
 "model": "fal-ai/flux-kontext-lora/inpaint",
 "strength": 0.22, "guidance_scale": 2.5, "steps": 50,
 "output_format": "png", "seed": 1394872001,
 "collage": {"scale": 0.47, "rotation_deg": -3.1,
             "coverage": 0.97, "colour_match": 0.8}}
```

Блок `collage` — отчёт первого шага: во сколько раз пришлось уменьшить лицо с
фотографии, на сколько градусов повернуть и какую долю лица шаблона накрыла
вклейка. При жалобе «не похож» смотреть надо сюда: `scale` больше 1 означает
растянутую мыльную вклейку, `coverage` ниже 0.9 — несовместимые ракурсы.

### Ошибки

Все — единым JSON `{"error": {"code", "message", "details"}}` из
`app/core/errors.py`:

| Код | HTTP | Когда |
| --- | --- | --- |
| `INVALID_IMAGE` | 400 | файл не читается, неподдерживаемый формат, битые параметры маски или коллажа |
| `PAYLOAD_TOO_LARGE` | 413 | файл больше `ML_MAX_UPLOAD_MB` |
| `NO_FACE_DETECTED` | 422 | mediapipe не нашёл лица — на обложке или на фотографии, в `details.image` видно, где именно |
| `MASK_MISSING` | 500 | маска не построена — дефект вызывающего кода, до сети запрос не доходит |
| `FAL_REQUEST_FAILED` | 502 | отказ fal: авторизация, баланс, сеть, ошибка модели, пустой ответ |
| `FAL_NOT_CONFIGURED` | 503 | не задан `FAL_KEY` |

Загрузка изображений в CDN fal обёрнута намеренно: она идёт до инференса и падает
первой, а необёрнутое httpx-исключение дошло бы до FastAPI как `500 text/plain` и
сломало бы JSON-контракт с Node.

## Конфигурация

Все настройки — из ENV с префиксом `ML_` (кроме `FAL_KEY`), единственное место
чтения — `app/config.py`. Полный список с комментариями — в `.env.example`.

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `FAL_KEY` | — | ключ fal.ai, **без префикса** `ML_` |
| `ML_COLLAGE_GROW_RATIO` | `0.02` | запас контура вклейки, доля высоты лица |
| `ML_COLLAGE_FEATHER_RATIO` | `0.01` | растушёвка края вклейки, доля высоты лица |
| `ML_COLLAGE_COLOUR_MATCH` | `0.8` | доля приведения тона вклейки к шаблону, 0..1 |
| `ML_FAL_MODEL` | `fal-ai/flux-kontext-lora/inpaint` | эндпоинт инференса |
| `ML_FAL_PROMPT` | см. `.env.example` | промпт стилизации |
| `ML_FAL_STRENGTH` | `0.22` | сила зашумления под маской, рабочий диапазон 0.15–0.30 |
| `ML_FAL_GUIDANCE_SCALE` | `2.5` | строгость исполнения промпта |
| `ML_FAL_STEPS` | `50` | шагов инференса (реально исполняется доля `strength` от них) |
| `ML_FAL_TIMEOUT_S` | `600` | таймаут скачивания результата |

| `ML_ALLOWED_ORIGINS` | `http://localhost:3000` | CORS, через запятую |

## Логирование и трассировка

JSON-логи пишутся в `logs/`:

| Файл | Содержимое |
| --- | --- |
| `logs/app.log` | активный файл: все записи, включая логи uvicorn |
| `logs/error.log` | активный файл: только `error` и выше |
| `logs/app.2026-07-23.1.log` | ротированные файлы |

### Ротация

`app/core/rotation.py` — `TimedRotatingFileHandler`, расширенный проверкой
размера, чтобы политика совпадала с Node (`pino-roll`):

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `ML_LOG_ROTATE_WHEN` | `midnight` | когда ротировать (`midnight`, `H`, `D`, `S`) |
| `ML_LOG_FILE_MAX_MB` | `20` | досрочная ротация по объёму |
| `ML_LOG_BACKUP_COUNT` | `14` | сколько ротированных файлов хранить |

Файл роняется по наступлению суток либо раньше при превышении объёма; имя
ротированного файла — `app.<дата>.<номер>.log`, как у Node. Индекс нужен для
нескольких ротаций по размеру за одни сутки.

Два отличия от Node — следствие устройства stdlib:

- активным всегда остаётся `app.log`, дата появляется только у ротированных
  файлов (у `pino-roll` датирован и активный файл);
- удаление старых файлов реализовано в `_prune()`: штатное опирается на схему
  имён stdlib и не находит файлы, переименованные `namer`. Сортировка идёт по
  дате и индексу из имени, а не по `mtime` — на Windows у файлов одной серии
  ротаций метки времени совпадают.

В консоль по умолчанию идёт читаемый формат; `ML_LOG_JSON=true` включает JSON и
там. Поля совпадают с Node-сервисом (`time`, `level`, `service`, `scope`,
`message`, `request_id`), поэтому логи двух сервисов грепаются одинаково:

```json
{"time": "2026-07-23T03:49:04.369Z", "level": "info", "service": "ml-service",
 "scope": "http", "message": "GET /health/ready → 503",
 "request_id": "trace-e2e-1784778544", "status_code": 503, "duration_ms": 3.84}
```

`RequestIdMiddleware` принимает `X-Request-ID` от Node.js API (или генерирует
UUID), кладёт его в `contextvar`, возвращает в заголовке ответа и пишет
access-лог со статусом и длительностью. Штатный access-лог uvicorn приглушён до
`WARNING`, чтобы не дублировать записи без `request_id`.

Произвольные поля добавляются через `extra`:

```python
log.info("маска лица построена", extra={"face_height": 316, "feather_px": 32})
```

## Структура

```
app/
  main.py                     точка входа, lifespan, CORS, обработчики ошибок
  config.py                   все настройки из ENV (префикс ML_)
  api/
    routes/health.py          /health и /health/ready — связь с Node.js API
    routes/face_swap.py       /face-swap, /face-swap/analyse
    schemas.py                контракт ответов для Node.js
    middleware/request_id.py  приём/генерация X-Request-ID + access-лог
  core/
    logging.py                JSON-формат, хендлеры, фильтр request_id
    rotation.py               ротация по времени и размеру, уборка старых файлов
    context.py                contextvar с request_id
    errors.py                 доменные ошибки → HTTP-коды
  pipelines/
    registry.py               диагностика для /health/ready (весов больше нет)
    collage.py                шаг 1: перенос лица подобием и жёсткая вклейка
    mask_generator.py         маска лица: полигон mediapipe, padding, растушёвка
    fal_api.py                шаг 2: транспорт до fal — загрузка, схема, скачивание
    face_swap/pipeline.py     оркестрация, единственный вход для API-слоя
  utils/image.py              кодирование/декодирование, BGR ndarray внутри
scripts/                      setup_venv.ps1 / setup_venv.sh
tests/                        pytest, работают без сети и без FAL_KEY
```

Разделение ролей: `collage.py` отвечает за сходство и не знает про fal;
`pipeline.py` решает, что и по какой маске обрабатывается; `fal_api.py` знает
только про транспорт до fal и ничего — про смысл операции.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Сеть не нужна: клиент fal подменяется фейком, детектор лиц — заглушкой из 468
точек. Проверяются перенос лица (в том числе то, что преобразование не может
исказить пропорции, а вклеенные пиксели совпадают с фотографией), объединение
контуров в маске, профиль её краёв, схема аргументов эндпоинта и диапазон
strength, обработка ошибок транспорта, ротация логов и проброс `X-Request-ID`.

Линтер — `ruff check app tests` (конфигурация в `pyproject.toml`).

## Интеграция с Node.js API

Node-сервис ходит на `http://localhost:8000` (`ML_SERVICE_URL`). Готовность этого
сервиса — готовность всего продукта: замена лица и есть его единственная работа,
поэтому Node отдаёт `503` на `/health/ready`, когда ML недоступен.

```js
const res = await fetch('http://localhost:8000/health/ready');
const ready = res.ok; // 503 → заказы принимать бессмысленно
```

Вызов долгий (облачный инференс — десятки секунд), поэтому Node дёргает
`/face-swap` только из фоновой задачи-воркера, а не из HTTP-обработчика.
