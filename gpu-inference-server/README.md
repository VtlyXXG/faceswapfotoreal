# gpu-inference-server — своя генерация на своей карте (Python 3.11 + FastAPI)

Сервер инференса, который снимает с проекта платные облачные пути. Ставится на
инстанс с картой (проверено на A40), **ключей и учётных записей не требует**, в
рантайме поднят с `HF_HUB_OFFLINE=1` — докачивать что-либо на первом заказе ему
запрещено.

Два пути живут здесь одновременно, и это не переходное состояние: они решают
разные задачи и опираются на разные модели.

## Рабочий путь: FLUX.2 + пересадка головы

`POST /v1/demo-render` — на вход фотография ребёнка и разворот книги, на выходе
готовый разворот. Один вызов на всё, синхронный: показ идёт вживую, и просить
заказчика опрашивать статус задачи ради тридцати секунд — плохой сценарий.

```
разметка шаблона  -> маска головы и её силуэт        (код ml-service)
сетка лица донора -> выровненный кроп лица           (код ml-service)
FLUX.2            -> кадр с новой головой, своя сцена
LaMa              -> шаблон со стёртой старой головой
transplant        -> голова из генерации в шаблон, остальное побитово
```

Порядок не переставляется: стирание идёт **по силуэту**, силуэт считается по
шаблону, и обе величины нужны пересадке одновременно.

Три вещи, которые стоит знать про этот путь:

**Стирание идёт по силуэту, а не по рабочей маске.** Маска расширена на два-три
десятка пикселей за голову, и LaMa заменила бы догадкой целый кусок фона. Нет
разметки — нет силуэта, и пересадка идёт без стирания, о чём в лог уходит
`warning`.

**Промпт — это запрет, а не описание.** Проверено на четырёх формулировках:
описание ракурса словами («голова отвёрнута и наклонена вниз») заставляло модель
довернуть голову ещё дальше, и лицо переставало находиться вовсе. Рабочая
формулировка запрещает менять ракурс, взгляд, положение волос и позу — она дала
одновременно лучшее удержание позы и лучшее сходство.

**Проходов по умолчанию ДВА, и это измеренное решение.** Первый несёт причёску
ребёнка с его фотографии, второй занят исключительно личностью и идёт по
результату первого. Причина: когда одну генерацию просят сразу про лицо и про
волосы, сходство падает на 0.04–0.07 и словами не возвращается — перебраны три
формулировки на двух зёрнах, все три хуже, самая подробная на трудном кадре
разрушила лицо до неузнаваемости детектором. Разделение прохода вернуло
личность: 0.512 → 0.532 на одном зерне и 0.450 → 0.587 на другом, то есть выше
прежнего переноса ОДНОГО лица (0.521).

Платим вдвое дороже кадром (70 с против 35) и большим разбросом от зерна к зерну.
`GPU_FLUX_PASSES=1` возвращает прежнее однопроходное поведение в точности —
режим оставлен рабочим, потому что без него «стало лучше» не с чем сравнивать.
Разбор целиком — в `tools/HAIR_EXPERIMENT.md`.

**Шаги выбираются по высоте лица в генерации, а не по доле кадра.** Восемь шагов
по умолчанию (на 16 хуже, чем на 8, при трёхкратном времени), но ниже 200 px по
высоте лица — шестнадцать: там вклеенная голова выходит вдвое мягче живописи, в
которую садится. Именно абсолютный размер, а не доля: у двух стендовых шаблонов
доля почти одна (17.5% против 17.6%), а ведут себя они противоположно.

**Шаблон приходит одним из двух способов, и ровно одним.** `base_image` —
картинка в запросе, как было; `template_id` — страница из каталога на диске
сервера (`GPU_TEMPLATES_ROOT`, раскладка `<книга>/<страница>.png`). Второй способ
появился ради книги: одиннадцать страниц подряд одним и тем же base64 означали бы
~90 МБ пересылки одних и тех же файлов на каждый заказ. Оба поля сразу или ни
одного — отказ `422`: заказ, про который нельзя сказать, что именно отрисовано,
хуже отказа.

Идентификатор — строчная латиница, цифры, `-` и `_`, необязательный один слэш
(`dino_pixar_real/cover`). Грамматика разрешающая, потому что идентификатор
превращается в путь на диске: всё, что она не пропускает, — либо опечатка, либо
попытка прочитать чужой файл. Присланные шаблоны приезжают с кириллическими
именами, поэтому при заливке они **переименовываются в ascii**; файл с именем
вне грамматики в каталоге не показывается — заказать его всё равно нельзя.

**Поля заказчика — `gender`, `age`, `hair_color` — принимаются и только
хранятся.** Они уезжают в `meta.child` и не делают с генерацией ничего: пол и
причёска и так приходят с фотографии донора (проход по волосам копирует длину и
цвет), а единственный руль, который к ним подошёл бы, — текст промпта, который
по замерам проекта сходство отнимает. Отдельно ждёт своего замера случай
«длинные волосы на коротко стриженном персонаже»: маска считается от геометрии
шаблона, и причёска крупнее шаблонной упирается в её кромку. `gender` —
закрытый список (`boy` / `girl`), потому что по нему однажды будет выбираться
профиль; `hair_color` — свободная строка, отказывать книге из-за слова, которое
ничего не делает, незачем.

`GET /v1/templates` отдаёт состав каталога с размерами файлов — проверка заливки
(«долетели ли все одиннадцать и целыми»). Число страниц видно и в `/health`
(`models.demo.templates`): пересозданная ВМ приходит без шаблонов вовсе, и узнать
это одним ответом дешевле, чем по отказам посреди заказа.

Страница показа на самом сервере — `GET /demo`: один шаблон, одна фотография,
одна картинка. Это отладочный одностраничник, а не панель книги: боевая панель
живёт на прокси (см. ниже). Выключается `GPU_DEMO=0`.

## Книга собирается ПОСТРАНИЧНО, и здесь нет типа заказа «книга»

Одиннадцать страниц (обложка и 10 разворотов) заказываются **одиннадцатью
отдельными вызовами `/v1/demo-render` подряд**, по одному за раз. Батч-эндпоинта
на всю книгу нет и заводить его не надо — решение принято по замерам, а не из
экономии:

* **Книга не влезает в один HTTP-запрос.** Полный прогон — 20–24 минуты работы
  карты против таймаута прокси `urlopen(timeout=900)`. Клиент получил бы `502`,
  а карта продолжила бы считать в пустоту.
* **Сторож гашения не увидел бы работы.** Прокси гасит машину по простою и
  считает простой от последнего ЗАПРОСА, а не от занятости GPU. Внутри одного
  длинного запроса `LAST_REQUEST` не обновляется — заказ, постоявший в очереди и
  потом посчитавшийся, пересёк бы порог и был бы погашен прямо во время рендера.
  Постранично каждая страница продлевает жизнь машине сама.
* **Отказ стоит страницу, а не книгу.** Упавшая страница повторяется поштучно.
* **Прогресс получается бесплатно** — панель показывает страницу сразу, как та
  готова, вместо двадцати минут молчания.

Состояния заказа на сервере тоже нет: заказ живёт во вкладке браузера, и его
теряет перезагрузка страницы. Это осознанный размен — постоянное хранилище
заказов, возврат к незакрытой книге и уведомления это отдельная работа, которая
к показу книги не требуется.

**Строго по одной странице за раз.** Слот на карте один (`GPU_QUEUE_SLOTS=1`):
одиннадцать параллельных запросов не ускорили бы ничего, а упёрлись бы в предел
длины очереди и вернули `503` на большей части страниц.

Панель книги — `wake-proxy/demo.html` в этом репозитории, развёрнута в
`/opt/wake-proxy/demo.html`. Превью считается ОДНИМ проходом (`passes: 1` в
запросе), книга — умолчанием сервера: 2–4 минуты против 5–7. Список страниц
зашит в панель, а не читается с `/v1/templates`: GET через прокси намеренно не
будит GPU-машину, и на спящем сервере список пришёл бы `503`.

## Ранний путь: SDXL + ControlNet + IP-Adapter

`POST /v1/template-render`, он же `POST /render` — алиас под уже написанный
клиент `HostedFluxPuLIDBackend` из `ml-service/app/pipelines/refine/adapter.py`.
Контракт запроса намеренно совпадает с тем, что собирает
`refine/payload.build_packet`, поэтому переезд на этот сервер стоит одной
переменной с базовым URL, а не правки пайплайна.

Внутри: LaMa стирает содержимое маски, SDXL inpaint (при наличии весов — под
ControlNet) рисует новое, CodeFormer поднимает лицо.

Личность входит через **IP-Adapter Plus Face на CLIP vision**, а не FaceID.
FaceID даёт заметно точнее сходство, но берёт identity из ArcFace-эмбеддинга
InsightFace, чьи официальные веса изданы под некоммерческой лицензией — для
платного продукта это блокирует использование целиком. Сходство здесь осознанно
обменяно на чистую лицензию (сам IP-Adapter — Apache 2.0).

`POST /v1/erase` — только стирание маски через LaMa, без генерации.

## Градация отказа

Ни один компонент не обязателен: отсутствие весов не роняет сервис, а понижает
качество — ровно как отсутствие весов разметки в ml-service понижает маску до
эллипса. Что именно живо, видно на `/health/ready` и в `meta.stages` каждого
ответа.

| Чего нет | Что происходит |
| --- | --- |
| SDXL | `503` на генерацию, сервис поднимается — для диагностики |
| ControlNet | обычный SDXL inpaint без структурного контроля |
| IP-Adapter | лицо рисуется по тексту, без сходства с донором |
| LaMa | стирание через `cv2.inpaint` (TELEA), заметно грубее |
| CodeFormer | лицо не восстанавливается, кадр отдаётся как есть |
| FLUX.2 | `503` на `/v1/demo-render`, остальные пути живы |

### Коды отказа демо-пути

| Код | Когда |
| --- | --- |
| `400 INVALID_IMAGE: …` | доменная ошибка ml-service — пересадка не собралась |
| `404` | `template_id`: такой страницы нет в каталоге сервера |
| `422` | разбор запроса, а также «на шаблоне не найден персонаж» и «на фото нет лица» |
| `503` | очередь переполнена, перегрузка (ожидание слота вышло), модель не загружена |
| `500` | настоящий сбой; наружу без подробностей, трассировка в журнале |

Ошибки ml-service несут свой код HTTP и машинный код сами, но их обработчик
живёт в приложении ml-service, а сюда приезжает только пакет `app` — поэтому
раньше они доходили до клиента голым `Internal Server Error`. Теперь опознаются
по составу полей (`status_code` + `code` + `message`) и отдаются своим кодом, а
машинный код едет в начале текста: `{"detail": "INVALID_IMAGE: …"}`. Опознание
утиное, а не импортом класса, намеренно — путь к пакету приходит из окружения, и
подъём сервиса не должен зависеть от наличия чужого кода.

**Ожидание в очереди ограничено 600 с, и это не круглое число.** Ожидание и
рендер идут внутри одного HTTP-запроса, а прокси автозапуска рвёт соединение на
900 с: 600 + 167 (обложка, самая дорогая страница) = 767. Поднимать предел —
только вместе с таймаутом прокси и в этом порядке, иначе клиент получит `502` от
прокси вместо честного `503` от очереди.

## Установка и запуск

Ставить **только на инстанс с картой**: `requirements.txt` тянет CUDA-сборку
torch через `--extra-index-url`. Проверка после установки — она же ответ на
вопрос «а карта-то видна»:

```bash
pip install -r requirements.txt
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
# ожидается 2.4.1+cu124 True, а НЕ 2.4.1+cpu False

python download_weights.py --root ./weights     # ~7 ГБ, заранее, не в рантайме
python download_weights.py --check              # что уже лежит

uvicorn server:app --host 0.0.0.0 --port 8100
```

`setup_server.sh` делает то же самое до systemd-юнита включительно; `Dockerfile`
собирает образ и слушает `8100`. CodeFormer ставится **отдельным шагом после**
основного набора (`facexlib`, затем принудительная переустановка
`opencv-python-headless`): facexlib объявляет зависимостью полный
`opencv-python`, оба пакета кладут один и тот же модуль `cv2` и перезаписывают
файлы друг друга. Порядок обязателен, подробности — в `requirements.txt`.

Веса качаются по манифесту в `download_weights.py`, и источники не прибиты
гвоздями: репозитории HuggingFace переезжают, файлы в релизах GitHub двигаются
между тегами. Чинится это переменными (`GPU_WEIGHTS_REPO_*`,
`GPU_WEIGHTS_URL_*`), а не правкой кода и пересборкой образа.

## Код ml-service не дублируется

Маску головы, разметку и пересадку сервер **импортирует** из пакета `app`
ml-service, а не копирует к себе: путь задаётся `GPU_MLSERVICE_PATH`. Код уже
написан, покрыт тестами и измерен, а копия разошлась бы с оригиналом на первой
же правке. Доли маски демо-пути (`GPU_DEMO_DILATE`, `GPU_DEMO_FEATHER`,
`GPU_DEMO_NECK`) намеренно совпадают с боевым `MaskProfile` там же.

Не найдя пакет, сервер поднимается, а `/v1/demo-render` отвечает `503` с
причиной — путь диагностируется, а не гадается.

## Настройки

Все — из окружения, префикс `GPU_`. Ключевые:

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `GPU_HOST` / `GPU_PORT` | `0.0.0.0` / `8100` | адрес прослушивания |
| `GPU_WEIGHTS_ROOT` | `./weights` | корень весов |
| `GPU_MLSERVICE_PATH` | пусто | где лежит пакет `app` из ml-service |
| `GPU_TEMPLATES_ROOT` | `./templates` | каталог шаблонов для `template_id`, раскладка `<книга>/<страница>.png` |
| `GPU_DEMO` | `1` | демо-путь и страница `/demo` |
| `GPU_FLUX_MODEL` | `black-forest-labs/FLUX.2-klein-4B` | модель демо-пути |
| `GPU_FLUX_STEPS` | `8` | шагов; выше — хуже при трёхкратном времени |
| `GPU_FLUX_STEPS_SMALL_FACE` | `16` | шагов, когда лицо мельче порога |
| `GPU_FLUX_SMALL_FACE_PX` | `200` | граница «мелкого лица», пиксели высоты |
| `GPU_FLUX_GUIDANCE` | `1.0` | режим дистиллированной модели; выше ломается |
| `GPU_FLUX_MAX_PIXELS` | `3 400 000` | потолок кадра: на 2048×2048 ловился OOM |
| `GPU_FLUX_PROMPT` | промпт-запрет | текст прохода по ЛИЦУ: второй проход на двух, единственный на одном |
| `GPU_FLUX_HAIR_PROMPT` | промпт причёски | текст ПЕРВОГО прохода на двухпроходной схеме |
| `GPU_FLUX_PASSES` | `2` | проходов генерации на кадр; `1` — прежнее поведение |
| `GPU_IP_ADAPTER_SCALE` | — | сила подмеса личности на пути SDXL |
| `GPU_QUEUE_SLOTS` / `GPU_QUEUE_MAX_WAITING` | `1` / `8` | одновременные генерации и длина очереди |
| `GPU_QUEUE_WAIT_TIMEOUT` | `600` | ожидание слота; потолок задан таймаутом прокси (900 с) |
| `GPU_DEVICE` / `GPU_DTYPE` | `cuda` / `fp16` | fp16 — единственный разумный режим SDXL на A40 |

Полный список — поиском по `_env(` в `server.py`; там же у каждого значения
написано, почему оно такое.

## Замеры качества

Стендовые мерки живут в `tools/` в корне репозитория и ходят на этот сервер по
`/v1/demo-render`. Локально нужен туннель до бокса:

```bash
ssh -f -N -L 8300:127.0.0.1:8300 deploy@<хост>
python tools/render_batch.py --seed 1234 --prefix S1234_
python tools/measure_batch.py FINAL_ S1234_
```

Адрес переопределяется `DEMO_URL` или `--url`. Что именно меряется, какие числа
уже врали и почему — в `tools/README.md`; читать его стоит **до** того, как
поверить числам.
